# connector-runtime 子计划 04：供给与加固

## 1. 目标

从「能用」到「可持续供给、可安全扩展」：OAuth top providers、连接器包格式、日志脱敏加固、限流。

## 2. 工作分解（中粒度）

| # | 模块 | 内容 | 验收 |
|---|---|---|---|
| S1 | OAuth2 授权码流程 | core 增加 oauth2 auth 类型：授权 URL 引导、回调换 token、刷新；桌面形态本地回调页，企业形态管理面发起 | 1 个真实 OAuth provider 建立连接并执行带 scope 的动作 |
| S2 | 连接器包格式 | 定义打包（定义 JSON + 图标 + 元数据）与签名校验；安装到 connectors 目录即入目录 | 签名无效的包被拒绝 |
| S3 | 脱敏加固 | 审计/错误信息中 Authorization、api_key、token 类值的递归脱敏全覆盖（含嵌套与数组） | 注入敏感值的输入在日志中全部呈 *** |
| S4 | 限流与配额 | 连接器级速率限制（令牌桶）；企业形态接现有配额 | 超限返回 429 语义错误码 |
| S5 | YAML 定义支持 | 定义加载层支持 YAML（加第三方依赖评估） | 同一定义 YAML/JSON 等价加载 |

## 3. 供给策略（沿母计划，不重建公共大目录）

- 企业：OpenAPI 导入内部应用（subplan 03 E5）+ 少量手工精修。
- C 端：精选高频连接器个位数起步（S1 逐个补 OAuth）。
- 外部网关条目保留，用户可自行接入。
