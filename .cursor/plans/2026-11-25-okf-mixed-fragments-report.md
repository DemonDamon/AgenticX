# 两条打架的知识：三个模型依据哪一条

12 个话题 × 2 种排列顺序 × 2 种呈现 × 3 个模型 × 每格 3 次，参照日期 2026-11-25，温度 0，已落盘 432 次调用。原始回答逐条保存在 datasets/okf_ablation/mixed_fragments_raw.jsonl。

## 怎么测

每个话题有两条互相矛盾的知识：一条已过期或已废弃（比如“退款审核 48 小时”），一条是现行的（“24 小时”）。两条同时给模型看，问同一个问题（“客服需要在多长时间内完成审核？”）。两条知识的标题相同，正文结构相同，只有数值不同。

- 不给户口：两条都只有正文，没有任何线索说明哪条现行
- 给户口：过期那条的 status 是 deprecated，或 stale_after 早于今天；现行那条 status 是 stable、stale_after 在今天之后

每个话题按两种顺序各排一次（过期的在前、现行的在前），用来发现“只依据排在前面的那条”。正确答案是现行那条的数值。

## 怎么读这些数

- 不给户口：三个模型几乎都答“无法回答”。不给户口的 216 次里，glm 和 DeepSeek 全部如此，MiniMax 有 3 次答了现行数值。两条知识只差一个数值，模型看得出它们互相矛盾，
  但没有任何信息说明哪条是现行的，所以不答。
- 给了户口：三个模型 216 次全部答现行数值。没有一次答过期数值，没有一次不答。两条知识先后顺序对调，结果不变。
- 模型之间：不给户口时，24 个“话题 × 顺序”里有 23 个三模型答案一致；给户口后 24 个全一致。

所以这个场景里，没有户口的问题不是答错，而是不答。三个模型不靠户口也基本一致，一致地不答。户口带来的是把“不答”变成“答对”，三个模型都一样。

结合单条知识的实验（cross_model_consistency.py）：只给一条过期知识、没有户口时，三个模型一致地照着过期内容答；两条知识矛盾、没有户口时，三个模型一致地不答。
两种情况下三个模型本来就很一致，缺的是答对。户口的作用是把“一致地错”和“一致地不答”都变成“一致地答对”，对三个厂商的模型效果相同。

### 这次实验的边界

1. 结果又是接近 0% 和 100% 的“天花板”数据，说明的是干净场景下三个模型都做得到。
2. 两条知识的标题和正文完全相同，只有数值不同，模型很容易看出矛盾。真实的过期文档和现行文档往往措辞不同，不一定这么明显。
3. 条目由实验者编写，都是企业内部知识；状态只有已废弃、已过期、正常三种，没有草稿、状态缺失这类中间情况。
4. 每格只重复 3 次，温度 0。
