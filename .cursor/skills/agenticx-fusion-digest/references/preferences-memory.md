# 内容偏好记忆：千人千面

同一个技能，装给不同的人或智能体，产出的读者、口吻、篇幅、关注点都可以不同。这些差异记在一份偏好文件里，由用户的反馈逐步积累，每次运行开头读取。

## 偏好文件

位置：状态目录下的 `preferences.md`。每个智能体（或每个用户）一份，不共用。

```markdown
# 内容偏好

## 读者
- 产品和研发负责人，熟悉 Agent 概念，不需要解释基础术语（2026-11-08，用户原话：「不用解释什么是 MCP」）

## 范式
- 日报控制在 2000 字以内（2026-11-09，「太长了，2000 字够了」）
- 每章最后的观察改叫「对我们意味着什么」（2026-11-10）
- 开头先放三条一句话要点，再进正文（2026-11-10）

## 关注与排除
- 多写开源项目和可落地的工程实践（2026-11-09）
- 不写融资新闻（2026-11-09）

## 配图
- 优先放架构图，数据图次之（2026-11-12）

## 适用范围
- 以上默认对日报生效；标了「调研」的条目只对定向搜集和聚焦专题生效
```

每条偏好一行：内容、日期、用户原话。分五类：读者、范式、关注与排除、配图、其他。

## 什么时候写入

用户对产出给出反馈时，先判断是一次性还是长期：

| 用户的说法 | 怎么处理 |
| --- | --- |
| 「以后都……」「每次都……」「记住……」 | 写入偏好文件，告诉用户记下了哪一条 |
| 「这篇……」「这次……」 | 只改这一篇，不写入 |
| 说不清是哪种（如「太长了」） | 先改这一篇，再问一句「以后都按这样写吗？」；非交互调用时只改这一篇 |

战略类智能体或调用方也可以通过参数直接传入偏好，效果和用户反馈相同，原话一栏写「调用方设置」。

写入后回复用户时，原样列出新增或修改的那一条，让用户能当场纠正。

## 怎么生效

- 每次运行开头读 `preferences.md`，把相关条目当作本次写作要求。
- 偏好可以覆盖技能里的默认值：篇幅、结构顺序、章节命名、关注领域、配图偏好、口吻。
- 偏好**不能**覆盖技能的硬规则：证据可核对、不编造、不用推测补空、来源可追溯、落盘失败不谎报。用户要求与硬规则冲突时（如「数字没出处也写上」），照硬规则做，并说明原因。
- 偏好之间冲突时，日期新的生效，旧的那条删掉，不保留两条互相矛盾的偏好。

## 保持精简

- 偏好文件控制在 40 条以内。超过时合并同类项（如三条关于篇幅的偏好合成一条），合并后保留最新日期。
- 用户说「忘掉……」「不用再……」时删除对应条目，并告诉用户删了哪条。
- 用户问「你记住了我哪些偏好」时，按分类列出全部条目。
