# 写法与改写对照

## 两句话检验

- 写完每章后问：只读过所有标题的人，能写出这一章的判断吗？能，就说明这章只是概要，要重写。
- 再问：把这章的观察删掉，剩下的是不是一篇新闻稿？是，就说明洞察不够，按下文「洞察的五种做法」补。

## 写作顺序：先判断，后证据

复述原文是最省力的写法，所以要用顺序挡住它。每章都按这个顺序起草：

1. 合上笔记，先写这一章的判断（一句）和观察（一到两句）。写不出来，说明这章还没想清楚，回到找主线那一步，不要靠堆细节撑篇幅。
2. 再打开笔记，只挑支撑这个判断所需的 1–3 条证据。和判断无关的细节，哪怕有趣也不放。
3. 最后补图和链接。

判断和观察是你的，不是原文作者的。原文作者的结论是证据，放进证据段并写明是谁说的；把它换个说法当成本章判断，等于没有判断。

## 洞察的五种做法

观察写原文没写的东西。下面五种做法都能产出这类内容。每章至少用前四种中的一种；第五种只能附加，不能单独充当观察。

| 做法 | 怎么做 | 示例句式 |
| --- | --- | --- |
| 算账 | 把两个来源的数字放在一起，算出原文没算的数 | 「A 的单价降了 X，B 的调用量涨了 Y，合起来每家的月账单其实涨了 Z。」 |
| 对撞 | 两个来源结论相反时，说清分歧在哪、你站哪边、为什么 | 「两篇的差别在样本：A 测的是新手，B 测的是专家，所以 B 的结论更适用于……」 |
| 反方 | 写出对本章判断最强的反驳，再说它为什么不成立，或在什么条件下成立 | 「最强的反驳是……；它成立的前提是……，本周的材料里这个前提不满足。」 |
| 预测 | 给出带条件、时间和可观测信号的预测，能在之后被证实或证伪 | 「如果……，三个月内会看到……；看不到，说明本章判断错了。」 |
| 检查项 | 读者明天就能做的一件事 | 「把系统里所有检查器失败时的行为列一张表。」 |

观察过不了下面任何一条，就重写：

- 换掉公司名、换到另一周，这句话照样成立吗？成立说明太泛。
- 有人能反驳它吗？没人能反驳的话，多半是正确的废话。
- 「这值得关注」「未来可期」「值得我们深思」「意义重大」一类句子，一律不算观察。

## 日报：各部分怎么写

### 标题

用一个判断句做文章标题，不用「AI 日报 11/7」这类栏目名。日期放在副标题或文首一行。

句式要换着用。「X 不在 A，在 B」「不是 A，是 B」「A 之后，B 成了新瓶颈」这类句式，读者连看几天就会麻木。写标题前查账本里最近 3 篇的标题，同一句式不连用。

### 文首日期行

正文第一行以 `YYYY-MM-DD · 覆盖 <起> 至 <止>` 开头，后面可以接扫描和深读的篇数。对账时只读这一行开头的日期。失败的源只写进运行日志。

### 开场（1 段，不超过 200 字）

从主线里的张力切入：一个数字、一个反常现象、两篇互相矛盾的结论。说出主线就停，不在开场里把每章的内容先讲一遍。不写「本期为大家带来」「今天有几件事值得关注」。

### 主题章节（2–3 个）

章节标题是判断句或问题，比如「专家在环，不等于专家在判断」，不写「Anthropic 动态」。

每章依次是判断、证据、图（有才放）、观察。这是行文顺序，不是小标题：成稿里不加「判断：」「观察：」这类标签，除非偏好文件要求。

- **判断**：第一句话就说结论。
- **证据**：来自至少两篇原文。写清实验怎么设计、样本多大、数字多少、和什么比。数字要能在原文找到。只写支撑判断所需的部分，不逐条转述原文的要点清单。
- **图**：放在它支撑的那段证据后面。图注一句，只说「看哪里」，不重复正文。
- **观察**：按上文「洞察的五种做法」写，一到三句。

### 另见（可选，最多 3 条）

达标但接不上主线的条目，不要硬塞进某一章。在这里每条写一句判断加链接。没有就省略这一节。

### 收束（3–4 条）

每条比章节再推进一步，可以把两章的结论合起来推出新判断。其中至少一条是「洞察的五种做法」里的预测。

检验方法：把一条收束删掉，如果正文里能找到意思相同的句子，它就是复述，换掉或删掉。

### 原文索引

每篇一行：`来源 · 标题`，标题带链接。不加摘要。

## 日报篇幅

- 深读 6–10 篇时，正文约 2000–3500 字。
- 深读 3–5 篇时，约 1200–2000 字。
- 单章不超过 800 字，其中证据不超过六成。超过了说明塞了不相干的材料，或者在复述原文。

## 删改一遍

初稿写完后，专门过一遍删改，再做自检。这一遍只删不加，目标是篇幅减少一到两成：

| 删什么 | 例子 | 怎么处理 |
| --- | --- | --- |
| 指路的空话 | 值得注意的是、有意思的是、最值钱的是、最锋利的是、真正的新东西是、需要交代的是、换句话说、也就是说 | 删掉这几个字，直接说内容 |
| 转述要点清单 | 「三个细节值得注意：一……二……三……」，三条都在复述原文 | 只留支撑本章判断的那一条，其余删 |
| 前情回顾链 | 「这接上 11-10 那期……11-13 那期又……」 | 只在本章确实推进了前期判断时写，每章最多一处、一句话、带日期 |
| 重复的术语解释 | 同一个词在一篇里解释两次，或给读者早就懂的词加括注 | 首次出现解释一次，括注不超过 15 字；偏好文件说读者懂的词不解释 |
| 背景铺垫 | 介绍公司或人物的来历超过两句 | 压成一句，或删掉 |
| 开场里的目录 | 开场把每章要讲的事列了一遍 | 只留主线那一句 |
| 重复的图注 | 图注和图下说明文字讲同一件事 | 只留一句 |

## 改写对照

### 条目式（不要）

> **11/4 ·** 用 Claude 调查 vault particles
> 原核细胞中 vault 样蛋白颗粒的首个 3D 结构。重点不只是结果，还有人与 Agent 如何一起找、分离、建模。
>
> **10/27 ·** Agent 如何塑造专家判断
> 随机试验：专业分析师与 coding agent 协作时，86% 会跟着 agent 被随机偏向的选项走。别默认「专家仍握有关键判断」。

问题：每源一段，各说各的；两篇明明在讲同一件事（人和 agent 到底谁在做判断），却没有连起来。

### 融合式（要）

> **专家在环，不等于专家在判断**
>
> 同一周里，Anthropic 发了两篇看起来不相干的研究。一篇是生物学家借助 Claude 解出原核细胞里 vault 样颗粒的首个 3D 结构；另一篇是随机对照实验：研究者让 coding agent 在分析任务里被随机设定偏向某个选项，结果 86% 的专业分析师最终选了 agent 偏向的那个。
>
> 放在一起看，结论比各自单看更尖锐：结构解析那篇成功，是因为每一步「找什么、怎么分离、模型对不对」都由人先提出假设、agent 执行验证；而对照实验里，分析师是在 agent 给出结论之后才介入，判断权在这一刻已经交出去了。
>
> （此处放对照实验的结果图：偏向组与对照组的选择比例。）
>
> 评估人机协作流程时，别只问「有没有人审核」，要问「人在 agent 出结论之前还是之后表态」。如果这个判断对，接下来半年里，把「先让人写预判、再展示 agent 建议」做成默认流程的产品会越来越多；一直看不到，说明顺从更多来自信息不对称，而不是表态顺序。

注意上面的数字和细节仅用于示范写法，实际写作必须以原文为准。最后一段用的是「洞察的五种做法」里的预测：给出时间范围、可观测的信号，以及什么现象会推翻它。

## 定向搜集报告

报告是给要做决定的人看的。读者可能只看第一节，所以第一节必须能独立成立。

### 结构

1. **标题**：主题加时间点，例如「企业内部 Agent 平台开源方案选型（截至 2026 年 11 月）」。
2. **结论**（3–6 条）：直接回答 `brief.md` 的主问题。每条一句判断，后面标置信度和引用，例如「多租户和细粒度权限是区分各方案的关键，只有两个项目原生支持（高）[3][7]」。用途是选型时，给出推荐和适用条件。
3. **范围与假设**：查了什么、没查什么、时间范围、采用了哪些默认值、哪些来源没访问成功。
4. **分节回答子问题**：每个子问题一节，节标题写成判断句。先判断，再证据，再观察（这对读者的决定意味着什么）。需要横向比较时用对比表，表格每格写事实，不写「较好」「一般」。
5. **分歧与不确定**：来源之间的矛盾、只有低置信度支撑的说法、变化很快的信息。
6. **没找到的**：查了但没有公开资料的问题，以及建议的补查方式（问厂商、看源码、做测试）。
7. **建议的下一步**：可选。读者接下来可以做的 2–4 件事。
8. **来源**：按 `[n]` 编号列出，每条写等级、发布方、日期、标题和链接。

### 写法要点

- 结论里的每一条，都要能在后面某一节找到展开和证据。
- 引用放在它支撑的那句话后面，不要整段末尾堆一串编号。
- 置信度只有高、中、低三档，定义见 `targeted-research.md` 第 5 步。
- 篇幅随深度：快速约 800–1500 字，标准约 3000–5000 字，深入不设上限，但每节不超过 1500 字，超过就拆。

## 文风

- 写给人看的编辑稿：具体、平实，名词和数字多，形容词少。
- 不用 emoji。不用「速览」「硬核」「重磅」「炸裂」「两边开花」「一文读懂」。
- 不连续用三个以上的排比句，不用「不是……而是……」反复起句。一篇里「不是……是……」最多出现两次，标题也算。
- 引用原文观点时说明是谁说的；自己的推断写成「我的判断是」或直接陈述，但不要假装是原文结论。
- 厂商自报的数字照写，但在同一句里标明「厂商自报」，不要等到章末才统一加保留意见。
