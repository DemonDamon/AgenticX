# 日报模式（冷启动巡检）

按监控源清单巡检新内容，写成一篇有判断的日报或周报。读者读完要带走判断，而不是一串标题。

这个模式难在两个取舍：哪几篇值得深读，哪几张图值得放。两者都按 `selection-rubric.md` 打分，不能凭第一印象挑。

## 输入

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| 监控源清单 | 状态目录下的 `watchlist.txt` | 冷启动时从本目录的 `watchlist-urls.txt` 复制一份；调用方给了别的路径就用调用方的 |
| 状态目录 | 调用方指定；没有则用落盘位置下的 `.state/` | 存放快照、账本、主题索引、偏好、监控源清单和聚焦专题，格式见 `dedup-ledger.md` |
| 落盘位置 | 本地文件夹 | 支持本地文件夹、飞书文档或知识库、GitHub 仓库，见 `delivery-sinks.md` |
| 时间窗 | 自上次快照以来 | 首次运行取最近 7 天 |
| 周期 | 日报 | 周报时账本窗口改为 8 周 |

## 冷启动

状态目录里没有快照时，视为冷启动：

1. 创建状态目录。把本目录的 `watchlist-urls.txt` 复制为状态目录下的 `watchlist.txt`，之后只改这份副本，技能自带的清单保持不变。
2. 时间窗取最近 7 天，照常扫源、打分、写稿。
3. 落盘成功后建立快照和账本。窗口外的旧条目一律记为 `dropped`，不进候选池，避免第二天把积压内容当新内容写。

冷启动的第一篇没有历史可以对照，跨天去重中的事件和观点两层不起作用，这是正常的。

## 扩充监控源

用户说「加上这个源」「以后也看看 X」，或调用方传入新 URL 时：

1. 抓一次该 URL，确认它是列表页（博客首页、研究页、更新日志页），能看到文章列表和日期。用户给的是单篇文章时，找到它所在的列表页，问一句是否改加列表页；非交互调用时直接加列表页。
2. URL 归一化后和清单比对，已经有了就告诉用户，不重复加。
3. 追加到 `watchlist.txt` 末尾，上一行写注释：`# 2026-11-09 用户添加：<一句说明>`。
4. 新源的第一次扫描按冷启动处理：只取最近 7 天，更早的条目记为 `dropped`。
5. 回复用户：加了哪个地址、它最近 7 天有几条更新。

删除源时把那一行删掉；暂停时在行首加 `#`，并在注释里写原因。不要动快照里该源的历史记录。

## 内容偏好

每次运行开头读状态目录下的 `preferences.md`，按里面的读者、范式、关注与排除、配图偏好来写。用户对成稿提反馈时，按 `preferences-memory.md` 判断是否写入长期偏好。偏好不能覆盖技能的硬规则。

## 跨天去重

不读前几天的日报全文，靠三层记录防止重复，每次读进上下文的历史内容有固定上限。细则见 `dedup-ledger.md`。

| 层 | 防什么 | 怎么做 |
| --- | --- | --- |
| URL | 同一篇原文再用一次 | 查快照，程序比对，不把快照读进上下文 |
| 事件 | 换了来源或 URL 的同一件事 | 对照最近 14 天账本里的事实和来源；没有新东西就不写，有增量只写增量并注明前情 |
| 观点 | 换了素材的同一个判断 | 对照最近 14 天账本里的主线和章节判断；要么推进一步，要么换主线 |

## 流程

### 0. 对账

开始前读落盘位置里最新一篇的文首日期。账本里没有这一天的记录，说明上次写入成功但记账失败，先按 `dedup-ledger.md` 补记，再开始本轮。

### 1. 扫源，只留新内容

逐个读清单里的源，记下每条更新的标题、日期、链接和一句话摘要。URL 归一化后与快照比对，只保留新出现的条目；再把候选池里 7 天内的 `pending` 条目加进来，一起进入第 2 步。

- 清单里空行和 `#` 开头的行是注释，跳过。
- 源失败时按 `SKILL.md`「来源访问失败」一节处理，不中断。
- 本轮要扫完清单里的全部源。自检时核对：成功数 + 失败数 = 清单中非空、非 `#` 开头的行数。

本步骤只读快照，不写快照。快照、账本都在第 7 步落盘成功后才更新。

有 `active` 状态的聚焦专题时，把新条目和各专题关键词比对，命中的写进该专题的 `inbox.jsonl`，规则见 `focus-tracking.md` 第 2 节。这一步不受日报落盘成败影响。

### 2. 给候选打分，选出深读名单

先读最近 14 天的账本和主题索引。对每条候选按五项打分（每项 0–2 分），细则见 `selection-rubric.md`。和账本里已写过的事件相同、又没有新数据或新结论的，「新信息」计 0 分：

1. **新信息**：有没有以前没有的数据、实验或能力，而不是旧观点换个说法。
2. **证据强度**：有对照实验、量化数字、可复现细节，还是只有宣称。
3. **决策影响**：读者看完会不会改变选型、架构或工作方式。
4. **跨源共振**：是否和本轮其他条目指向同一个问题。
5. **非显而易见**：只读标题的人能不能猜到结论。猜得到就是 0 分。

命中 `high` 优先级聚焦专题的条目，「决策影响」至少计 1 分。偏好文件里「排除」的内容直接 0 分。

总分 ≥ 6 进深读名单，按分数取前 6–10 篇；不足 3 篇达标时，只写达标的那几篇，不要拿低分条目凑篇幅。营销稿、招聘稿、活动预告、纯版本号更新直接 0 分。

打分结果写进状态目录的 `digest-selection.md`（每条一行：分数、链接、一句理由），不进正文，用来让人复核判断。

### 3. 深读，抽证据和候选图

深读要读正文，不要只读摘要。每篇抽出：

- 核心论断，一句话。
- 支撑它的证据：数字、实验设计、对照组、产品细节，带出处段落。
- 作者没说但可以推出的东西，或你不同意的地方。
- 候选图：正文里的数据图、结构图、对比图、关键截图。抽取方法见 `figure-extraction.md`。

### 4. 找主线，再动笔

先回答：这批材料共同把哪个问题推到了台前？用一句话写出来，这句话要能被反驳。

- 好的主线：「Agent 提效之后，专家在环不等于专家在判断。」
- 坏的主线：「本周 AI 领域进展很多。」

找不到主线就别硬写综述。只写 1–2 个真有判断的主题，篇幅短一些没关系。

主线定下后，对照最近 14 天账本里的主线和章节判断。基本相同时，要么在前次基础上推进一步并点明承接关系，要么换一条主线。

### 5. 选图

按 `selection-rubric.md` 的选图四问逐张过，四项都是「是」才放。全文一般 2–5 张；一张都不达标就不放图。

### 6. 写

结构和写法见 `writing-guide.md` 的「日报」部分；偏好文件里对结构、篇幅、章节命名的要求优先于下面的默认结构：

1. **开场**，1–2 段：用主线把材料串起来，不写目录式导读。
2. **2–4 个主题章节**：章节标题写成判断句或问题。每章跨 2 篇以上来源，依次是判断、证据、图（有才放）、观察。
3. **收束**：3–5 条判断，每条都要比章节内容再推进一步。
4. **原文索引**：每篇一行，标题加链接。

### 7. 落盘和自检

先过 `SKILL.md` 的通用自检，再加三项：

- [ ] 成功数 + 失败数 = 清单中非空、非 `#` 开头的行数；失败的源记在运行日志里，不写进正文。
- [ ] 逐章对照最近 14 天账本的主线和章节判断，没有原样重复；写过前情的事件只写了增量，并注明了前情日期。
- [ ] 文首有日期行，供下次对账。
- [ ] 偏好文件里的每条要求都已体现，或在结果里说明为什么没体现（如与硬规则冲突）。

按 `delivery-sinks.md` 落盘。落盘成功后，按顺序更新：快照（进稿条目标为 `used`，未达标的标为 `pending`，0 分条目和过期候选标为 `dropped`）、追加一条账本、压缩 14 天前的账本进主题索引。落盘失败时三者都不动。

## 没有新内容时

没有达标条目，就不生成文章、不发「今日无更新」，也不在落盘位置写失败摘要。只在运行日志里记一行扫了哪些源、各自状态。快照照常更新：新条目进候选池，过期候选标为 `dropped`；账本不动。
