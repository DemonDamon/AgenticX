# 去重：快照、候选池与已发布账本

本文件只用于日报模式。定向搜集模式的增量处理见 `targeted-research.md` 末尾「与已有资料的关系」。文中「目标文档」指主落盘位置里最新一篇日报，落盘方式见 `delivery-sinks.md`。

目标：今天的稿子不重复前几天写过的事和观点，同时每次运行读进上下文的历史内容有固定上限，不随天数增长。

做法是不读旧日报全文，只读两份结构化记录：

| 文件 | 管什么 | 读法 | 上下文占用 |
| --- | --- | --- | --- |
| `digest-snapshot.json` | 哪些 URL 看过、各自状态 | 用脚本或 `jq` / `grep` 查询，不整份读进上下文 | 几乎为零 |
| `digest-ledger.jsonl` | 已发布文章写过哪些事、哪些观点 | 只读最近 14 天的条目 | 约 5000–7000 字 |
| `digest-themes.md` | 14 天以前的主题索引 | 整份读，每个主题一行 | 很小，只随主题数增长 |

路径默认在工作目录，调用方可以另行指定。三份文件都由本技能维护，不手改。

## 第一层：URL 去重（确定性）

### URL 归一化

比对前统一处理：

- 去掉 `#` 之后的片段。
- 去掉追踪参数：`utm_*`、`spm`、`scm`、`from`、`ref`、`accounttraceid`。
- 去掉末尾的 `/`，域名转小写，`http` 视同 `https`。

### 快照格式

```json
{
  "checked_at": "2026-11-09T16:00:00+08:00",
  "sources": {
    "https://www.anthropic.com/research": {
      "seen": [
        {"url": "https://...", "title": "...", "date": "2026-11-04",
         "first_seen": "2026-11-07", "status": "used", "used_in": "2026-11-08"},
        {"url": "https://...", "title": "...", "date": "2026-11-06",
         "first_seen": "2026-11-08", "status": "pending", "last_score": 5}
      ]
    }
  }
}
```

`status` 三种取值：

| 状态 | 含义 | 下次运行怎么处理 |
| --- | --- | --- |
| `used` | 已写进某篇已发布的稿子 | 永不再作为新条目；有后续进展时按第二层「增量」处理 |
| `pending` | 看过，分数不够没写，进入候选池 | `first_seen` 起 7 天内，每次运行和新条目一起重新打分；超过 7 天改为 `dropped` |
| `dropped` | 营销稿、0 分条目，或候选池过期 | 跳过 |

旧快照里没有 `status` 字段的条目，一律当作 `dropped`。

候选池的意义：某条单看只有 5 分，过两天出现了呼应它的新材料，「跨源共振」上去后可能达标进稿。候选池条目重新打分时，只用快照里存的标题和摘要；进了深读名单才重新抓正文。

## 第二层：事件去重（模型判断）

打分前，把每条候选和最近 14 天账本里的 `facts` 和 `sources` 比对：

- **同一件事，没有新东西**（同一次发布、同一个实验、同一组数字，只是换了来源或换了说法）：「新信息」计 0 分，在 `digest-selection.md` 里注明「已于 2026-11-08 写过」。
- **同一件事，有实质增量**（新数据、新实验、官方修正、出现反例）：正常打分。进稿时只写增量部分，并写明「11 月 8 日的日报写过前情」，附链接，不重讲背景。
- **拿不准**：打开账本里对应那天的原文链接核对。只开这一篇，不批量读旧稿。

## 第三层：观点去重（模型判断）

定主线（流程第 4 步）和写完各章后，各对照一次最近 14 天的 `thesis` 和 `chapters`，以及 `digest-themes.md`：

- 主线或某章判断与已有条目基本相同：要么往前推进一步（前次提出问题，这次给出反例、边界或解法，并点明承接关系），要么换一条主线。
- 不允许原样再写一遍同一个判断，即使素材是新的。

## 账本格式

每发布成功一篇，追加一行 JSON：

```json
{"date": "2026-11-08", "title": "专家在环，不等于专家在判断", "doc": "<文档链接或本地路径>",
 "thesis": "Agent 提效之后，专家在环不等于专家在判断",
 "chapters": ["专家在 agent 出结论之后才表态，判断权就已交出", "..."],
 "sources": [{"url": "https://...", "title": "..."}],
 "facts": ["随机对照实验中 86% 的分析师选了 agent 被随机设定偏向的选项", "..."]}
```

- `facts` 每条一句话，只记会被别家重复报道的事实和数字，一篇 5–15 条。
- 单条记录控制在 500 字以内。

## 窗口与压缩

- 日报：读最近 14 天的账本。周报：读最近 8 周（一周一条）。
- 每次运行时，把超出窗口的账本条目压进 `digest-themes.md`：每个主题一行，格式为 `主题判断句 | 首次日期 | 最近日期 | 次数`。已有主题只更新最近日期和次数。
- 压缩后的账本条目可以留在文件里，但不再读进上下文。

## 交付与对账

顺序固定，不能颠倒：

1. 写入目标文档（飞书或本地 Markdown）。
2. 写入成功后，才更新快照（本轮进稿的条目改为 `used`，其余按规则设为 `pending` 或 `dropped`）、追加账本、压缩主题索引。
3. 写入失败：快照和账本都不动，下次运行会重新处理这批内容。
4. 本轮没有达标条目、不出稿：快照照常更新（新条目进候选池，过期候选改为 `dropped`），账本不动。

每次运行开始时先对账：读目标文档开头的日期（文首日期行），如果账本里没有这一天的记录，说明上次写入成功但记账失败。此时先从该文档反推一条账本记录（标题、主线、章节判断、原文索引、关键数字），并把索引里的 URL 在快照中标为 `used`，再开始本轮。

## 能保证什么，不能保证什么

- URL 去重是程序比对，同一篇原文不会被重复采用。
- 事件和观点去重靠模型对照账本判断，能挡住绝大多数重复，但不保证 100%。交付自检里逐章对照最近 14 天的判断句，是最后一道防线。
- 窗口外的旧主题只剩索引里的一行。隔一个月再写同一主题，模型知道写过，但看不到当时的细节；需要时按索引日期打开那一篇。
