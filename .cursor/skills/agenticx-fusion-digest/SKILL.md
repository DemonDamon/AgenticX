# 情报搜集

把散落的信息变成有判断、可追溯的成稿，并落盘到用户指定的位置。三种模式共用一套选材、核实、写作和落盘标准。

## 两种角色

同一个技能，装给不同的智能体，承担不同的角色：

| 角色 | 做什么 | 主要用到 |
| --- | --- | --- |
| AI 日报助手 | 冷启动巡检监控源，每天或每周出一篇有判断的日报；用户可以随时加源扩大范围；按用户反馈记住内容偏好，越用越贴合这个人 | 日报模式、监控源扩充、偏好记忆 |
| 情报分析专家 | 以日报为底，用户或战略类智能体（如产品战略助手）判断某类新内容值得吸收进产品体系时，为它建立聚焦专题，持续在深度和广度上优先搜集分析，沉淀出一份全面的专题情报；也接受一次性的定向调研 | 聚焦专题、定向搜集 |

两个角色可以由两个智能体分别承担，也可以由同一个智能体兼任。分开时，各自的 `state_dir` 必须不同，否则快照、账本、偏好会互相干扰。

## 选模式

| 用户或调用方在说 | 模式 | 细则 |
| --- | --- | --- |
| 写今天的 AI 日报、跑一下周报、巡检一下监控源 | 日报：从监控源清单出发，只看新内容，跨天去重 | `references/daily-digest.md` |
| 帮我调研 X、X 和 Y 怎么选、深度研究 X | 定向搜集：从一个问题出发，多轮检索、交叉核实，一次产出 | `references/targeted-research.md` |
| 把 X 方向作为重点持续盯、对日报里的 X 做专题情报、战略智能体发来专题请求 | 聚焦专题：持续多轮深挖，与日报联动，累积成一份全面情报 | `references/focus-tracking.md` |
| 把这几篇（用户贴来的链接或文章）融会贯通写一篇 | 日报的写作部分，跳过扫源和去重，从第 2 步打分开始 | `references/daily-digest.md` |

拿不准时：只想知道最近出了什么，走日报；有一个具体问题、一次答完即可，走定向搜集；要长期跟踪某个方向，走聚焦专题。

## 两项贯穿所有模式的能力

- **扩充监控源**：用户说「加上这个源」时，验证是列表页、去重后追加到状态目录里的清单副本，新源按冷启动处理。见 `references/daily-digest.md`「扩充监控源」。
- **内容偏好记忆**：用户说「以后都……」时，把读者、范式、关注与排除、配图等偏好记进状态目录的 `preferences.md`，每次运行开头读取。偏好可以改默认写法，不能改硬规则。见 `references/preferences-memory.md`。

其他细则按需读取：打分和选图看 `references/selection-rubric.md`，写法看 `references/writing-guide.md`，取图看 `references/figure-extraction.md`，落盘看 `references/delivery-sinks.md`，日报跨天去重看 `references/dedup-ledger.md`，常见疑问看 `references/faq.md`。

## 装配给智能体

调用方用这些参数配置，缺省时用右列默认值。参数写在智能体的人设或定时任务指令里即可：

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `mode` | `daily` / `research` / `focus` | 按上文「选模式」判断 |
| `question` | 定向搜集要回答的问题 | `research` 模式必填 |
| `focus` | 聚焦专题请求，字段见 `references/focus-tracking.md`；或已有专题的短名，表示跑下一轮 | `focus` 模式必填 |
| `depth` | `quick` / `standard` / `deep` | `standard` |
| `watchlist` | 监控源清单路径 | 状态目录下的 `watchlist.txt`，冷启动时从 `references/watchlist-urls.txt` 复制 |
| `add_sources` | 本次要加入监控源的 URL 列表 | 无 |
| `preferences` | 调用方直接设定的内容偏好，写入方式同用户反馈 | 无 |
| `product_context` | 产品能力说明文档的路径，聚焦专题据此写「对产品的启示」 | 无；没有时不写该节 |
| `sinks` | 落盘位置列表，写法见 `references/delivery-sinks.md`：`local:<目录>`、`local-temp`、`feishu`、`feishu:<位置>`、`github:<仓库>:<目录>`、`github-new:<仓库名>:<目录>` | `local:./intel` |
| `state_dir` | 快照、账本、偏好、监控源清单、聚焦专题的存放位置 | 主落盘位置下的 `.state/` |
| `interactive` | 能否向用户提问 | `true`；定时任务和后台调用设为 `false` |

`interactive` 为 `false` 时不提问：缺省项一律用默认值，把采用的默认值写进报告的「范围与假设」或运行日志。

每次运行结束，给调用方返回一段简短结果：模式、落盘位置和链接、采用的来源数、失败的源及原因。没有产出时说明原因（如「无达标新内容」）。聚焦专题另外返回轮次、增量简报和需要发起人决定的事。

## 运行前提与限制

| 需要什么 | 缺了会怎样 |
| --- | --- |
| 网页搜索和网页正文抓取工具 | 定向搜集无法检索、日报无法扫源。停止并说明缺这项能力；用户直接贴来的材料仍可照常写 |
| 能查看图片的多模态能力 | 不能按「先看图」选图。退回 `references/figure-extraction.md` 的保守规则，拿不准就不放图 |
| `lark-cli` 且已登录 | 飞书来源记为失败并跳过；飞书落盘改写到本地文件夹，并说明原因 |
| `git` 和已登录的 `gh` | GitHub 落盘改写到本地文件夹，并说明原因；公开仓库仍可通过网页读取 |
| 能访问海外站点的网络 | 部分海外博客、论文站、GitHub 可能超时。成稿只基于实际读到的材料，不补写没读到的内容，并在结果里列出缺席的来源 |

这些限制只会让素材变少，不会让流程中断。

## 来源访问失败

所有模式都按这张表处理，处理完继续读其余来源：

| 失败类型 | 怎么判断 | 处理 | 日志里写什么 |
| --- | --- | --- | --- |
| 超时、连接重置、5xx | 无响应或服务端错误 | 隔约 5 秒重试一次，仍失败则跳过 | `超时，已重试 1 次；若持续失败，可能需要可访问海外站点的网络` |
| 404、410 | 页面不存在 | 不重试 | `URL 已失效，建议从清单删除或换成新地址` |
| 401、403、登录墙 | 跳转登录页，或正文是登录提示 | 不重试 | `需要登录；飞书来源请先执行 lark-cli auth login` |
| 反爬拦截 | 验证码页、挑战页、429 | 不重试，本轮跳过 | `被站点拦截，下次再试；连续多次失败可改用浏览器抓取` |
| 内容无法解析 | 拿到页面但找不到正文或日期 | 不重试 | `页面结构无法识别，需要人工确认地址` |

飞书文档和知识库来源用 `lark-cli docs +fetch --as user` 读取；GitHub 来源优先读 README、Release、Issue 和提交记录，可用 `gh` 命令或网页。

## 共用的硬规则

- **有判断，不罗列。** 每一节先说结论，再给证据。禁止「日期 · 标题 + 两句摘要」的条目堆砌。
- **证据可核对。** 每个数字、每个事实都能在来源里找到出处。找不到就写「未找到公开资料」，不用推测补空。
- **选材要打分。** 日报按五项打分选文，定向搜集按来源分级定结论强度；配图一律过选图四问。都不能凭第一印象挑。
- **写原文没写的东西。** 观察、推论、边界、分歧才是成稿的价值，复述原文结论不算。
- **文风。** 不用 emoji，不用「速览」「硬核」「重磅」「两边开花」这类口号，不连续用三个以上排比。
- **落盘可信。** 写入失败时改写到本地并原样说明原因，不声称已写入。

## 通用自检

交付前逐项检查，任一项不过就改。各模式的细则文件里还有附加检查项。

- [ ] 随便抽一节，能找到判断、可核对的证据，以及原文没写的观察或推论。
- [ ] 每个数字都能在来源里找到出处，会变的数字（价格、Star 数、版本）写了取数日期。
- [ ] 每张图都过了选图四问，没有重复、没有封面图。
- [ ] 文中链接和来源清单都能点开。
- [ ] 失败的来源记在运行日志或结果说明里，不写进正文。
- [ ] 每个落盘位置的结果（成功的链接或路径、失败的原因）都已告诉调用方。
