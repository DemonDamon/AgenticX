### 核心曲线

```
CTR
  ↑
  │     seed-03 ●  (高耦合, CTR=1.17, 团队涌现)
  │
1 ├────────────────── 持平线
  │
  │  seed-01 ●  (低耦合, CTR=0.80, 团队次优)
  │
  │  seed-02 ●  (中耦合, CTR=0.33, 团队次优)
  │

```

**结论：协作税随任务耦合度递减——低耦合任务分工收益小而通信开销大（CTR<1），高耦合任务分工收益超过通信开销（CTR>1）。核心叙事成立。**

## 三、关键发现

### 1. 协作税的 token 维度

团队模式的 token 消耗始终高于个体模式（1.65x ~ 8.28x），这就是"协作税"的直接量化：

- 低耦合（周报）：团队 token 比高达 **5.25-8.28x**，但质量反而下降 → 纯损耗
- 高耦合（数据核对）：团队 token 比仅 **1.65-2.98x**，但质量提升 → 分工收益覆盖了通信开销

**这个发现极为重要：协作税不仅影响质量，更直接体现在 token 成本上。低耦合任务花 8 倍 token 得到更差结果，是"个体最优、团队次优"的最直观证据。**

### 2. 高耦合任务的涌现条件

seed-03 seed 1 出现 CTR=1.333 的团队涌现：
- 个体模式只拿到 0.75 分（单 agent 处理 100+ 条记录有遗漏）
- 团队模式拿到 1.0 分（A/B 双源并行核对 + 合并去重，各 50 条独立处理）
- token 比仅 1.65x（分工效率最高）

**这说明：当数据量超过单 agent 处理阈值时，分工从"开销"变为"增益"——这正是协作税曲线的拐点。**

### 3. seed-02 seed 0 核验异常

seed-02 风险预警 seed 0 的个体和团队质量都是 0.000，原因：LLM 输出格式未命中核验器的关键词匹配规则（如"风险清单"/"根因分析"等章节标题用了不同措辞）。seed 1 的质量正常（0.833/0.556）。

**对策：正式实验需用 LLM-judge 替代关键词核验，避免格式差异导致的误判。当前简化核验器仅用于决策门快速验证。**

## 四、局限性（决策门 → 正式实验的改进点）

| 维度 | 决策门（当前） | 正式实验（Phase 1+） |
|---|---|---|
| Agent 框架 | 简化版（串行 LLM 调用） | AgenticX AgentTeamManager（真实多 Agent 事件流） |
| 质量核验 | 关键词/结构断言 | LLM-judge + 人工验证子集 |
| 任务数 | 3 | 50-100 |
| 模型数 | 1（DS V4 Flash） | 4-5（轻量档 + 旗舰档） |
| Seeds | 2 | 3+ |
| 指标 | CTR + token 比 | CTR + 协调开销 + 协议合规度 + 过程感知 |
| 统计检验 | 无 | Mann-Whitney U / 效应量 |
