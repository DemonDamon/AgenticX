## 2. Datasheet for Datasets

按 Gebru et al. 的标准模板，落盘 `paper/release/DATASHEET.md`。必答的关键问题及本项目的答案要点：

### Motivation
- **为什么创建这个数据集？** 现有 agent 基准无法回答"加 agent 是否划算"；且已有多智能体评测从不报告产出装配方式。
- **谁资助的？** 如实填写。

### Composition
- **实例是什么？** 每个实例是一个办公任务变体，含：任务描述、共享初始数据、角色卡、验收规范（`required_sections` / `expected_sets` / `expected_values`）、参数取值记录。
- **多少个？** 45 个种子任务 × 10 变体 = 450 实例（按 `03` §2.1 目标）。
- **是采样还是全集？** 变体由参数化生成器从声明的参数空间采样，参数空间定义随代码发布。
- **含个人信息吗？** 任务中的人名、部门名均为**虚构素材库**（`task_generator.py` 的 `NAMES_POOL` 等），不含真实个人信息。**必须在此明确声明**。
- **含敏感或冒犯性内容吗？** 需在 FIX-7 完成后声明"不含对真实第三方产品的负面评价"（当前 `t-CONTENT-H-03` 违反此项，见 `01` B6）。

### Collection Process
- **数据如何获得？** 全部为程序化合成，基于对通用办公工作流的抽象，**不含任何真实企业数据**。这一点要写清楚，既回应隐私问题也回应"任务真实性"质疑。

### Preprocessing / Cleaning
- 参数化生成流程、ground truth 推导方式、变体去重校验（`validate_variants.py`）。

### Uses
- **推荐用途**：多智能体协作机制的受控评测、装配协议研究、团队级指标开发。
- **不推荐用途**：作为真实企业办公能力的绝对度量；作为模型通用能力排行依据。**明确写出来**，避免被误用。

### Distribution / Maintenance
- 见本文 §5、§6、§7。

## 4. Croissant 元数据

NeurIPS D&B 要求提供机器可读的数据集元数据（Croissant 格式，基于 schema.org）。

落盘 `paper/release/croissant.json`，最小骨架：

```json
{
  "@context": {"@vocab": "https://schema.org/", "cr": "http://mlcommons.org/croissant/"},
  "@type": "sc:Dataset",
  "name": "TeamBench",
  "description": "A paired individual-vs-team benchmark for LLM agent collaboration with assembly protocol as a controlled variable.",
  "license": "https://creativecommons.org/licenses/by/4.0/",
  "url": "<Zenodo DOI>",
  "version": "1.0.0",
  "citeAs": "<bibtex>",
  "distribution": [
    {
      "@type": "cr:FileObject",
      "@id": "teambench-tasks.zip",
      "contentUrl": "<url>",
      "encodingFormat": "application/zip",
      "sha256": "<hash>"
    }
  ],
  "recordSet": [
    {
      "@type": "cr:RecordSet",
      "@id": "tasks",
      "field": [
        {"@type": "cr:Field", "@id": "tasks/task_id",   "dataType": "sc:Text"},
        {"@type": "cr:Field", "@id": "tasks/scenario",  "dataType": "sc:Text"},
        {"@type": "cr:Field", "@id": "tasks/coupling",  "dataType": "sc:Text"},
        {"@type": "cr:Field", "@id": "tasks/roles",     "dataType": "sc:Text"},
        {"@type": "cr:Field", "@id": "tasks/verification", "dataType": "sc:Text"}
      ]
    }
  ]
}
```

校验：用 MLCommons 的 `mlcroissant` 包验证格式合法。

```bash
.venv/bin/pip install mlcroissant
.venv/bin/python -c "
import mlcroissant as mlc
ds = mlc.Dataset(jsonld='paper/release/croissant.json')
print('croissant valid:', ds.metadata.name)
"
```

## 5. 许可证

**代码与数据必须分别声明**，这是 D&B 审稿人会检查的细节。

| 资产 | 建议许可 | 文件 |
|---|---|---|
| 代码（runner / scorer / generator / adapters） | Apache-2.0 或 MIT | `paper/release/LICENSE-CODE` |
| 任务数据与生成产物 | CC-BY-4.0 | `paper/release/LICENSE-DATA` |
| 模型输出轨迹（artifact 全文） | CC-BY-4.0，并注明由各厂商模型生成 | 同上 + `NOTICE` |

**`NOTICE` 文件必须说明**：轨迹数据由 DeepSeek / Moonshot / Zhipu / OpenAI 等模型生成，其使用受各自服务条款约束；发布者不对模型输出内容负责。这一条能挡掉"发布模型输出是否合规"的质疑。

### 8.2 复现脚本

`paper/release/reproduce.sh`，必须支持三档：

```bash
#!/usr/bin/env bash
# 用法: bash reproduce.sh {smoke|subset|full}
#   smoke  —— 3 任务 × 1 seed × 1 模型，约 10 分钟，验证环境
#   subset —— 15 任务 × 2 seed × 1 模型，约 2 小时，复现主要趋势
#   full   —— 论文全量，约 N 小时，需 API 预算
set -euo pipefail
MODE="${1:-smoke}"
: "${TEAMBENCH_API_KEY:?请设置 TEAMBENCH_API_KEY}"
...
```

**smoke 档必须能在没有大额预算的情况下跑通**，这是审稿人实际会执行的那一档。

### 8.3 结果核对

提供 `paper/release/expected_smoke_results.json`，让复现者能比对自己的输出是否在合理范围内（考虑到 LLM 采样随机性，给区间而非精确值）。

## 9. 加分项

### 9.1 Holdout split

把 45 个种子任务划为 `public`（35）与 `holdout`（10），holdout 的 ground truth 不公开，只通过评测服务提交。这是对抗污染的实质性措施，比"参数化生成"更有说服力。

### 9.2 Leaderboard

即使是一个静态的 GitHub Pages 表格也好过没有。字段：模型 / 框架 / 装配协议 / CTR_matched / CO / TMS / 提交日期。

### 9.3 任务浏览页

一个简单的静态页面，可视化展示每个任务的角色卡、输入数据、验收标准、以及 single/team 两种产出样例。审稿人能快速理解任务长什么样，对评分很有帮助。
