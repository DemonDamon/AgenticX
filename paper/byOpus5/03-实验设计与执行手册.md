## 1. 实验总体设计

### 1.1 从"对比两种模式"升级为"析因实验"

v0.1 的设计是 `mode ∈ {single, team}` 的两点对比。新设计把 `01` 中发现的混杂变量提升为受控因子：

| 因子 | 水平 | 数量 | 说明 |
|---|---|---|---|
| **assembly**（装配协议） | last / concat / integrator / blackboard | 4 | **本论文的核心新因子** |
| **mode**（执行模式） | single / single_refine_k / single_bon_k / team | 4 | 后三者算力对齐 |
| **coupling**（耦合度） | L / M / H | 3 | 原有因子 |
| **scenario**（办公场景） | DOC / DATA / PROJ / CROSS / CONTENT | 5 | 原有因子 |
| **model** | ≥4 个，≥3 家族，含 ≥1 闭源 | 4–6 | 见 §1.3 |
| **seed** | ≥3 | 3 | 原为 2，不足 |

注意 `assembly` 只作用于 team 模式，所以完整的执行臂是：

```
arms = {single, single_refine_k, single_bon_k}
     ∪ {team × assembly ∈ {last, concat, integrator, blackboard}}
     = 3 + 4 = 7 条臂
```

### 1.2 消除已知混杂（必做）

| 混杂源 | v0.1 现状 | 新要求 |
|---|---|---|
| 采样温度 | Kimi 强制 1.0，其余 0.3 | **全部模型统一 T=1.0**（因为部分模型不支持其他值），并在论文中说明；或全部改用支持 T=0 的模型 |
| seed 生效性 | T=1.0 时 seed 不传 | 若模型不支持 seed，则**放弃"可复现单次运行"的说法**，改为报告 3 次独立采样的均值与标准差 |
| 供应商路由 | GLM 走聚合平台，其余走一方 | **全部走各厂商一方端点**；做不到则该模型的跨家族比较结论必须删除 |
| 字数预算 | 单体 4000 / 团队角色 2800 | FIX-2 已统一为同一 `char_budget` |
| 上游截断 | 固定 4000 字符 | 提为参数，主实验用 16000（近似不截断），另设消融 |

### 1.3 模型选择

| 档位 | 建议 | 作用 |
|---|---|---|
| 中档开源 | DeepSeek-V4-Flash | 保留，与旧数据可比 |
| 旗舰开源 | DeepSeek-V4-Pro | 家族内能力梯度 |
| 跨家族旗舰 | Kimi-K3 或 GLM-5.3（二选一，走一方端点） | 跨家族验证 |
| **闭源旗舰** | GPT / Claude / Gemini 任一 | **必须有**。v0.5 的 Limitation 1 自承无闭源结果，这是审稿人必问项 |

最少 4 个模型。若预算允许，做到 6 个（每家族 2 档）以支撑能力梯度分析。

## 2. 任务集扩容（M1、M2）

### 2.1 目标规模

| 项 | v0.1 | 目标 |
|---|---|---|
| 种子任务 | 15（每格 1 个） | **45**（5 场景 × 3 耦合 × **3 个不同任务**） |
| 每任务变体 | 0（生成器是空函数） | **10** |
| 实例总数 | 15 | **450** |
| 主实验采样 | 全部 | 每任务随机取 3 个变体 → 135 个实例 |

### 2.2 新增 30 个任务的设计约束

每个新任务必须满足**五项硬性要求**，缺一不可：

1. **单体可完成**：单智能体在预算内能产出完整交付物（否则 CTR 分母失效）。
2. **角色分工非平凡**：不能是"把文档切三段"这种伪分工；角色之间必须有真实的信息依赖或视角差异。
3. **ground truth 可机器判定**：`expected_sets` / `expected_values` / `expected_counts` 至少有一项非空，且能从生成过程直接推导。
4. **末位角色职责跨越两种类型**：同一个 (场景, 耦合) 格子里，3 个任务中至少 1 个是天然整合型收尾、1 个是天然切片型收尾——**这样才能在任务层面而非仅在协议层面测量装配效应**。
5. **参数化维度 ≥3**：至少三个可变参数（实体数、数值范围、约束条件），保证 10 个变体互不相同。

### 2.3 场景×耦合的任务矩阵（建议填充）

| | Low | Medium | High |
|---|---|---|---|
| **DOC** | 周报汇总 / 会议纪要整理 / 术语表合并 | PRD 评审 / 技术方案评审 / 用户手册改版 | 合同交叉审阅 / 多方案比选 / 标书应答拆解 |
| **DATA** | 渠道汇总 / 月度指标表 / 问卷频次统计 | 预算偏差分析 / 漏斗转化归因 / 库存周转 | 跨源核对 / 多口径对账 / 异常检测与归因 |
| **PROJ** | 迭代回顾 / 任务清单归并 / 工时汇总 | 风险预警 / 依赖梳理 / 里程碑健康度 | 资源冲突重排 / 多项目排期 / 关键路径博弈 |
| **CROSS** | 入职 checklist / 多部门问卷回收 | 客诉工单处理 / 跨部门流程改造 | 季度需求仲裁 / 跨部门事故复盘 / 预算分配谈判 |
| **CONTENT** | 推文生产 / 产品简介 / FAQ 撰写 | 多平台文案适配 / 图文脚本 | 发布会全稿 / 危机公关多稿 / 多语种同步 |

粗体的已有任务保留（改造为参数化），其余为新增。

## 3. 真实框架适配（B2、M8）

### 3.1 目标

证明结论不是自建串行管线的特例。**最少接入 2 个框架**。

推荐 LangGraph + AutoGen：Python API 稳定、可精确控制角色与消息流、可注入自定义装配步骤。

### 3.2 适配层规范

**新建** `paper/infra/adapters/`：

```
paper/infra/adapters/
  __init__.py
  base.py            # TeamAdapter 抽象基类
  lightweight.py     # 现有 LightweightTeamRunner 包装为 adapter
  langgraph_adapter.py
  autogen_adapter.py
```

`base.py` 定义统一契约：

```python
class TeamAdapter:
    name: str
    def run(self, task: dict, seed: int, assembly: str,
            char_budget: int) -> RunResult:
        """必须返回与 LightweightTeamRunner 完全同构的 RunResult，
        其中 total_tokens / llm_calls 必须包含框架自身的所有开销
        （含框架内部的规划、路由、反思调用），否则 CO 不可比。"""
```

**关键约束**：三个 adapter 必须使用**相同的角色卡、相同的输入数据、相同的装配协议、相同的字数预算**。框架之间只允许在"协作机制"上有差异。

### 3.3 框架实验的作用

论文中回答两个问题：
1. 装配协议效应是否在真实框架上复现？（若复现 → 结论具备普适性）
2. 框架的默认装配方式是什么？（这一点本身是有价值的发现：多数框架默认取最后一个 agent 的输出，与本文发现的最差协议一致）

## 4. 人工效度验证（M4）

| 项 | 要求 |
|---|---|
| 抽样比例 | ≥20% 的 artifact（主实验约 2000+ runs → 抽 400 份） |
| 标注者 | ≥2 人独立，互不可见 |
| 盲化 | 隐藏 mode / model / assembly，文件名用哈希 |
| rubric | 与 L3 judge 完全相同 |
| 报告 | 标注者间 Krippendorff α；Q vs 人工的 Spearman ρ（整体 + 分 L1/L2/L3 层） |
| **接收线** | **α ≥ 0.67 且 ρ ≥ 0.6**，否则回炉改 FIX-3 |

工具见 `02` FIX-6。

## 5. 人类基线（M3）

抽 10%（约 5 个任务 × 3 变体）由人类完成，记录：
- 完成时长（分钟）
- 产出经同一打分器打分的 Q
- 主观难度评分（1–5）

作用：在论文中回答"这些任务对人类是否也有难度"，以及"agent 距离人类基线还有多远"。TheAgentCompany 因为缺人类基线被批评过，OSWorld 有人类基线（72.36%）是加分项。

## 6. 实验执行矩阵与命令

### 6.1 主实验（Experiment 1：装配协议效应）

**这是论文的头条实验。**

```
臂数 = 7（3 单体 + 4 装配协议）
任务 = 45 种子 × 3 变体 = 135 实例
seed = 3
模型 = 4
runs = 7 × 135 × 3 × 4 = 11,340
```

若预算不足，按以下顺序砍：变体 3→2（−33%）、模型 4→3（−25%）、任务 45→30（−33%）。**不要砍装配协议的 4 个水平**，那是论文主张所在。

保守配置（推荐起步）：`7 臂 × 45 实例 × 3 seed × 4 模型 = 3,780 runs`

命令模板：

```bash
cd /Users/damonli/myWork/AgenticX
for ASM in last concat integrator blackboard; do
  .venv/bin/python paper/infra/teambench_runner.py \
    --tasks-dir paper/tasks/data/v2 \
    --seeds 0 1 2 \
    --model deepseek-v4-flash \
    --assembly "$ASM" \
    --char-budget 4000 \
    --scorer v2 \
    --out paper/experiments/v2/exp1_dsflash_${ASM} \
    2>&1 | tee paper/experiments/v2/exp1_dsflash_${ASM}.log
done
```

单体基线（三条臂）：

```bash
for BL in single single_refine_k single_bon_k; do
  .venv/bin/python paper/infra/teambench_runner.py \
    --tasks-dir paper/tasks/data/v2 --seeds 0 1 2 \
    --model deepseek-v4-flash --single-baseline "$BL" \
    --char-budget 4000 --scorer v2 \
    --out paper/experiments/v2/exp1_dsflash_${BL}
done
```

> `--single-baseline` 需在 FIX-2 中一并加到 argparse，并在 `run_experiment` 里分派到 `paper/infra/single_baselines.py` 的对应函数。

### 6.2 Experiment 2：耦合度 × 装配 交互

用 Experiment 1 的数据切分即可，**无需额外运行**。分析目标：验证"控制装配协议后耦合度效应是否仍存在"。这直接回应 `01` B1 中的 Simpson 悖论。

### 6.3 Experiment 3：框架泛化

```
框架 = 3（lightweight / langgraph / autogen）
装配 = 2（last / integrator，取效应两端）
任务 = 15（每格 1 个代表任务）
seed = 3，模型 = 2
runs = 3 × 2 × 15 × 3 × 2 = 540
```

### 6.4 Experiment 4：消融

| 消融 | 变量 | 水平 | runs |
|---|---|---|---|
| A. 上游截断长度 | `TB_UPSTREAM_CTX_LIMIT` | 1000 / 4000 / 16000 | 15×3×3×1模型=135 |
| B. 团队规模 | 角色数 | 2 / 3 / 4 / 6 | 需任务支持可变角色数，15×4×3=180 |
| C. 打分器版本 | `--scorer` | v1 / v2 | 复用已有 artifact 重新打分，**0 次 LLM 调用** |
| D. L3 judge 开关 | on / off | 2 | 复用 artifact，仅 judge 调用 |

消融 C 特别重要：它回答"结论是否依赖打分器实现"，是审稿人会问的稳健性问题。且成本极低。

### 6.5 预算估算

按均价 ¥0.02 / 1K tokens、单 run 平均 25K tokens 粗估：

| 实验 | runs | 预估 token | 预估成本 |
|---|---|---|---|
| Exp1 主实验（保守） | 3,780 | ~95M | ¥1,900 |
| Exp3 框架泛化 | 540 | ~16M | ¥320 |
| Exp4 消融 A+B | 315 | ~8M | ¥160 |
| Exp4 消融 C+D | 0 新增 / judge ~2M | ~2M | ¥40 |
| 人工验证 judge 复跑 | ~400 | ~2M | ¥40 |
| 失败重跑余量 20% | — | — | ¥500 |
| **合计** | ~5,000 | ~123M | **约 ¥3,000** |

闭源模型（GPT/Claude）单价高 5–20×，若纳入需单独预算，建议只在 Exp1 的核心子集（15 任务 × 2 装配 × 3 seed = 90 runs）上跑。
