## 3. 核心判断：为什么说"有救"

三个事实支撑这个判断：

**事实一：选题缺口是真的。** 现有 agent 基准（TheAgentCompany / GAIA / SWE-bench / OSWorld / AgentBench）确实都以单 agent 为分析单位，"配对式个体—团队对比"确实没有基准在做。这个缺口成立，不需要改。

**事实二：那个 bug 揭示的现象比原论文的现象更有价值。** 原论文想说"团队比个体差 4–7%"。实测数据显示：**同一批任务、同一批模型，仅仅改变"团队最后一步是谁产出交付物"，CTR 就从 0.87 跳到 1.03**——差异 0.16，是原论文所有效应量的 3 倍以上；在控制耦合度后差异达到 0.27，是 5 倍以上。也就是说，"多智能体划不划算"主要不取决于模型多强、agent 多少个，而取决于**产出如何装配**。这是一个更强、更可操作、更没人系统做过的结论。

**事实三：时间够。** NeurIPS 2027 D&B 截稿约在 2027 年 5 月，距今约 9 个月。按 `03` 的排期，修代码 3 周 + 扩任务 6 周 + 主实验 6 周 + 人工验证 3 周 + 写作打磨 8 周，有约 6 周缓冲。**前提是立刻停止在旧 runner 上继续产数据。**

## 4. 重构后的论文一句话主张（建议采用）

> 现有关于"多智能体是否优于单智能体"的结论，混淆了**协作本身**与**产出装配协议**。TeamBench 通过配对式个体—团队评测，把装配协议提升为一等受控变量，并证明：**装配协议解释的 CTR 方差远大于模型能力与团队规模之和**——在正确装配下团队可以稳定跑赢个体，在朴素装配下再强的模型也救不回来。

这条主张的好处：
- 把已有的负面结果（团队更差）转化为**条件性结论**（在什么条件下更差），审稿人更买账；
- 天然解释了为什么此前工作结论打架（他们的装配协议各不相同且未报告）；
- 给了框架开发者可执行的行动项，D&B track 很吃这个；
- **不需要推翻已有数据**——旧数据变成 `assembly=last` 这一档的实验臂，一分钱不浪费。
