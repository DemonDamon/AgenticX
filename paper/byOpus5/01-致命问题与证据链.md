## B1（最高优先级）团队产出装配丢失：论文全部头条发现的真正来源

### 代码定位

`paper/infra/teambench_runner.py`

- `LightweightTeamRunner.run()`，L285–317
- 关键行 **L301**：`last_output = r["content"]  # 最后一个角色的输出 = 团队产出`
- 关键行 **L309**：`output=last_output`
- 配套：`_TEAM_SYSTEM` 常量 L186–191，明确要求每个角色**"只专注完成你的分内工作……输出就是你分内的交付物"**

### 现象

团队模式下 N 个角色各自产出一份分内交付物，但只有**最后一个角色**的文本被当作团队的最终产物送去打分。前 N−1 个角色实际完成的工作被丢弃。

而 `ArtifactScorer.score()`（L333–493）用的是 `task["verification"]["required_sections"]` —— 也就是**整份交付物**的章节清单。于是团队被要求用一个角色的切片，去满足整份文档的验收标准。

### 证据（可复现）

该任务要求四个章节：主演讲稿 / 竞品对比 / 技术Q&A / 业务Q&A。团队的四个角色**分别产出了这四部分**，但只有第四部分进入评分，于是 L1 掉到 0.463。这不是协作损耗，是管线丢数据。

### 效应量对比（这才是最关键的部分）

按"最后一个角色是否承担整合职责"把 15 个任务分成两组：

- **integrator-final**（末位角色产出完整交付物）：`t-DOC-L-01`(撰写员/整合为结构化周报)、`t-PROJ-L-01`(报告撰写员/整合为迭代回顾报告)、`t-CONTENT-L-01`(润色员/润色全文)、`t-DOC-H-03`(冲突消解员/merge)、`t-DATA-H-03`(合并员/merge)、`t-PROJ-H-03`(排期冲突消解员/solver)、`t-CROSS-H-03`(优先级仲裁员/arb)

**读这张表要看三件事：**

1. **同一耦合档内部**，装配方式造成的 CTR 差是 **0.276（低耦合）** 和 **0.270（高耦合）**。
2. 论文报告的三个主发现效应量分别是 **−0.047**（团队次优）、**−0.017**（能力转移悖论）、**+0.077**（PROJ 甜蜜点）。混杂变量的影响是它们的 **3.5–16 倍**。

论文口径（仅 5 个正式模型目录）下的显著性检验：

```

slice-final      n=16 meanCTR=0.883
Mann-Whitney U=48  z=-3.33  p=8.7e-04  Δ=0.130
```

### 为什么致命

- **Finding 1（耦合律）** —— 被证伪，是 integrator 占比 3/5、0/5、4/5 造成的假象。
- **Finding 2（团队普遍次优）** —— 无法归因，8/15 任务的团队产物本身就是残片。
- **Finding 5（PROJ 甜蜜点）** —— PROJ 的 L 和 H 任务末位都是整合角色，这解释了它为什么"唯一 CTR>1"，与"项目跟进是聚合型任务"这个理论解释无法区分。
- **§5.5 的 "semantic relay penalty"** —— 中耦合档在 L3 打开后掉得最狠，作者为此发明了一个术语；但中耦合档的 integrator 占比是 **0/5**，五个任务的团队产物全是残片。这个"发现"就是这个 bug。

### 修复指针

`02-代码修复规范.md` FIX-1：把装配协议提升为显式参数 `--assembly {last,concat,integrator,blackboard}`，默认 `integrator`；旧行为保留为 `last` 作为实验对照臂。

## B2 评测对象不是多智能体系统（构念效度）

## B3 打分函数缺乏效度且系统性奖励冗长

### B3-a：L1 结构分是字符袋检验

**定位**：`teambench_runner.py:349-353`

```python
words = [c for c in re.sub(r"[^\u4e00-\u9fffA-Za-z0-9]+", "", sec)]
if not words: l1 += 1; continue
hits = sum(1 for c in words if c in output)
ratio = hits / len(words)
l1 += min(ratio / 0.8, 1.0) if ratio >= 0.5 else 0
```

`words` 是把章节名拆成的**单个字符**列表。`c in output` 检查的是**该字符是否在全文任意位置出现**。所以章节"本周进展"只要全文里分别出现过"本""周""进""展"就算命中，与是否真有这个章节无关。

**后果**：输出越长，任意汉字出现的概率越高，L1 越高。这是一个纯粹的长度奖励。

**复现**：

```bash
cd /Users/damonli/myWork/AgenticX
python3 -c "
import re
def l1(sec,out):
    w=[c for c in re.sub(r'[^\u4e00-\u9fffA-Za-z0-9]+','',sec)]
    r=sum(1 for c in w if c in out)/len(w)
    return min(r/0.8,1.0) if r>=0.5 else 0
print('章节名=本周进展')
print('  完全无关的长文本得分:', l1('本周进展','本次会议讨论了周期性问题，团队推进了展会筹备工作'))
print('  真正含该章节的文本 :', l1('本周进展','## 本周进展\n完成了三项工作'))
"
```

实测：无关长文本同样拿满分 1.0。**打分器无法区分"有这个章节"和"碰巧用了这几个字"。**

### B3-b：L2 数值分是"文中离目标最近的那个数"

**定位**：`teambench_runner.py:434-437`（及 438–442 同构）

```python
nums = [float(x) for x in re.findall(r"[-+]?\d[\d,]*\.?\d*", output.replace(",",""))]
tgt = float(V["expected_total_qty"])
best = min(nums, key=lambda n: abs(n-tgt)) if nums else 0
_numeric_assert("total_qty", best, tgt, 0.9)
```

从产出中抽出**所有**数字，取离目标最近的那个来比对。输出里数字越密集，越可能有一个碰巧落在 ±10% 容差内。这不测正确性，测的是数字密度。

### B3-c：L3 恒为常数 0.6，CTR 被加性偏置污染

**定位**：`teambench_runner.py:470-482`。基线实验全部在 `--disable-llm-judge` 或 judge 未启用下运行，`l3_score = 0.6` 写死。

于是 `Q = 0.5·L1 + 0.3·L2 + 0.2·0.6 = 0.5·L1 + 0.3·L2 + 0.12`。

CTR = Q_team / Q_single 中，分子分母各含一个 **+0.12 的固定加项**，会把比值系统性地拉向 1。§5.5 打开 L3 后 CTR 普遍下降 0.05–0.06，作者解读为"语义质量被计入后团队损失更大"——但其中有多少只是去掉常数项的机械效应，论文没有分离。

### B3-d：长度不对等与打分长度偏好叠加

- 单体字数上限 4000（`_prompt_single`，L162）
- 团队每角色上限 2800（`_TEAM_SYSTEM`，L189）
- 团队最终产物 = 最后一个角色的输出 ≤ 2800

结合 B3-a/B3-b 的长度奖励，**团队产物先天承受约 30% 的字数劣势**，而打分函数恰好奖励长度。"团队质量更低"至少部分是"团队产物更短"的同义反复。论文从未报告长度控制后的结果。

### 修复指针

`02` FIX-3：新建 `paper/metrics/scoring_v2.py`，L1 改为 Markdown 标题结构解析 + 同义词表（长度不变），L2 改为强制结构化答案块 + 集合级 P/R/F1，L3 关闭时**重归一化权重**而非注入常数。`02` FIX-6：人工标注 ≥20% 子集验证 Q 的效度。

## B7 算力不对等比较，缺 compute-matched 单体基线

### 现象

团队消耗 2.4–3.4× token、3–4× LLM 调用；单体只有 1×。论文据此得出"团队更贵且质量更低"。

但**正确的对照是同等算力下的单体**。这是 More Agents Is All You Need 之后该领域的标准要求。

### 为什么致命

审稿人必问："你给单体同样的预算了吗？" 如果单体跑 3 轮自我修订之后质量也涨了 5%，那么"团队不划算"的结论就变成"你只是没给单体同样的钱"。这个反驳一旦成立，论文的核心叙事直接塌方。

### 修复指针

`02` FIX-2：新增三条单体基线臂
- `single`：1 次调用（现状，保留）
- `single_refine_k`：k 轮串行自我修订，k = 团队角色数（LLM 调用数对齐）
- `single_bon_k`：best-of-k 采样 + 选择器（token 数对齐）

CTR 的主定义改为对 **compute-matched 单体**取比值，对 `single` 的比值作为附录补充。

### B8-a：温度不一致

### B8-b：Kimi 的 seed 从未生效

T=1.0 时 seed 不传。**Kimi 的"两个 seed"只是两次无控制的随机采样**，不具备可复现性，却与 DS/GLM 的受控 seed 一起进入同一张表。

### B8-c：供应商路由混杂

Limitation 6 自承 GLM-5.3 走聚合平台（TokenHub），其余走一方端点。而"能力转移悖论"的第三个家族证据正是 GLM。

### B8-d：功效不足且无功效分析

15 任务 × 2 seed = 每模型 30 对，每格约 10。论文自己承认 3 个 Finding 不显著。以观察到的效应量（0.02–0.05）估算，检出跨家族梯度所需样本远超当前规模。

### B8-e：承诺的 FDR 校正未执行

`团队级指标形式化定义-v0.1.md` §5 末句："所有 $p$ 值做 Benjamini-Hochberg FDR 校正"。稿件 §5.7 报了十余个 p 值，无一处提及。

### 修复指针

`02` FIX-5 + `03`：统一温度（全部 T=0.0 或全部 T=1.0，二选一并说明）；统一走一方端点；seed ≥3；样本量按功效分析确定；改用混合效应模型 `Q ~ mode*coupling*assembly + (1|task) + (1|model)` 替代成堆的两两检验；对保留的两两检验做 BH-FDR。
