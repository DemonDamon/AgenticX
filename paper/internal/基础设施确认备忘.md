## 二、可复用基础设施清单

| TeamBench 需求 | AgenticX 模块 | 复用确认 |
|---|---|---|
| 多 Agent 团队并发执行 | `AgentTeamManager.spawn_subagent` | `async def spawn_subagent(*, name, role, task, tools=None, ...)` 返回 `{"ok":bool,"agent_id":str}` |
| 轨迹落盘 | `event_emitter` 回调 + `RuntimeEvent` | 收到 `SUBAGENT_STARTED/COMPLETED/PROGRESS`、`TOOL_CALL/RESULT`、`ROUND_START/END`、`CONTEXT_STATS`、`FINAL`、`ERROR` 等 23 种事件 |
| 产出物收集 | `SubAgentContext.artifacts: Dict[Path,str]` + `summary_sink` 回调 | 每个 subagent 的产物与摘要独立收集 |
| 状态查询 | `manager.get_status(agent_id)["subagent"]["status"]` | `SubAgentStatus`: PENDING/RUNNING/PAUSED/COMPLETED/FAILED/CANCELLED |
| 并发控制 | `max_concurrent_subagents` 参数 | 可配团队规模上限（对应 TeamBench 团队规模维度） |
| 会话隔离 | `owner_session_id` + `collect_global_statuses(session_id)` | 防止跨实验 run 污染（对应多次 seed 重跑） |
| 超时治理 | `run_timeout_seconds` + `AGX_SUBAGENT_MIN_RUN_TIMEOUT_SECONDS` | 长程任务超时地板（办公长程任务需要） |
| 工具白名单 | `tools: Optional[Sequence[str]]` 参数 | 可按 Agent 角色限制工具集（对应分工卡） |

**关键发现：协调开销指标所需数据（通信轮次、token、工具调用数）全部已在事件流中**——`CONTEXT_STATS` 含 token 统计，`TOOL_CALL` 计数即工具调用数，`ROUND_*` 计数即通信轮次。TeamBench 的"协调开销"指标可直接从事件流聚合计算，无需额外埋点。

## 三、文档 API vs 实际 API 的差异（重要）

`docs/guides/multi-agent.md` 展示的 API 与实际实现有出入，开发时以实际代码为准：

| 项 | 文档展示 | 实际实现 |
|---|---|---|
| 构造 | `AgentTeamManager(agents=[...], max_concurrency=3)` | `AgentTeamManager(llm_factory, base_session, event_emitter, summary_sink, max_concurrent_subagents, owner_session_id)` |
| 启动 | 列表预定义 agents | `await spawn_subagent(name, role, task)` 动态 spawn |
| 通信 | A2A `A2AClient/A2AServer` | 实际为 meta-agent 分发模式（spawn + summary 回收） |

**对 TeamBench 的影响**：评测 runner 应基于实际 `spawn_subagent` API 开发，而非文档示例。
