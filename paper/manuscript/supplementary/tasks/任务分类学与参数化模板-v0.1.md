## 一、三维正交分类学

团队级办公任务沿三个独立维度划分，每个维度选择互不相交的档位，确保任务空间的覆盖性。

| 维度 | 档位 | 说明 |
|---|---|---|
| 团队规模 $N$ | 2 / 3 / 4 | 多少个 subagent 参与协作 |
| 任务耦合度 | 低 / 中 / 高 | 任务内部子任务的信息依赖强度（能否真并行） |
| 办公任务类型 | 文档协作 / 数据分析 / 项目跟进 / 跨部门沟通 / 内容生产 | 任务的业务语义 |

**三维笛卡尔积 = 3 × 3 × 5 = 45 个格子。Phase 1 目标覆盖 15 个格子（每个办公类型 × 3 档耦合度各至少 1 个），Phase 2 扩展到 50+。**

### 耦合度的操作定义（用于任务设计时定性判断）

| 档位 | 判断标准 | 预期现象 | 示例 |
|---|---|---|---|
| **低耦合** | 子任务可完全分离，无交叉信息依赖，合并仅需简单拼接/去重 | CTR < 1（通信开销 > 分工收益） | 多人写周报：各写一段然后合并 |
| **中耦合** | 子任务有单向信息传递（流水线式），上游输出是下游输入，但无循环依赖 | CTR ≈ 1（分工收益 ≈ 通信开销，拐点区） | 风险预警：收集→分析→建议 |
| **高耦合** | 子任务需双向依赖或真并行后交叉校验 / 多方决策 / 对抗协作 | CTR > 1（分工收益 > 通信开销，涌现区） | 数据核对：A/B 双源核对 + 合并冲突消解 |

### 办公任务类型的操作定义

| 类型 | 代表性任务 | 典型 artifact 形式 |
|---|---|---|
| 文档协作 | 周报撰写 / PRD 评审 / 合同审阅 / 会议纪要整理 | Markdown / Word 文档 |
| 数据分析 | 销售与库存核对 / 经营看板制作 / 预算偏差分析 / AB 实验结果解读 | 表格 / CSV / 报告 |
| 项目跟进 | 风险预警 / 迭代回顾 / 发布清单核对 / 资源排期冲突检测 | JSON 看板 / 项目报告 |
| 跨部门沟通 | 客户投诉响应链 / 新员工入职流程 / 跨部门需求对齐 / 培训计划排期 | 邮件 / 工单 / 流程文档 |
| 内容生产 | 产品宣发稿多人校对 / 技术文档翻译+审校 / 活动方案创意+评审 / 演讲稿润色 | 文案 / 演讲稿 / 文档 |

## 二、15 任务设计（Phase 1 覆盖）

**每个任务的必含字段**（和 seed 数据结构保持一致，确保 runner 一次实现即可）：

```
task_id          唯一标识，如 "t-DOC-L-01" （类型-耦合度-序号）
task_type        low / medium / high 耦合度
office_type      document / data / project / cross_dept / content
team_size        推荐 subagent 数（2 / 3 / 4）
description      一句话任务说明
roles            [{name, role, responsibility, tools}]   团队模式分工卡
shared_initial   共享初始态 dict （成员记录、表格、看板等）
team_prompt_seed 团队模式总指令（说明角色关系）
single_prompt_seed 个体模式总指令（单人怎么做）
verification     {required_sections, asserts, expected_values, ...}
params           可参数化的字段（模板生成器用）
```

### 设计特点

- **耦合度覆盖**：每类文档/数据/项目/跨部门/内容各 1 低 1 中 1 高 → 5×3=15 任务正好覆盖所有 (办公类型, 耦合度) 组合。团队规模梯度随耦合度自然增长（2→3→4）。
- **抗污染设计**：每个任务的 `shared_initial` 字段中，成员记录、表格行数、SKU 编号、日期、项目 ID 等都标为 `params`，生成器可随机替换。
- **难易度梯度**：高耦合任务 N=4，artifact 更复杂，L1+L2 断言更严格。Phase 1 的基线实验中难易度梯度应能体现在 Q 分上。

## 三、参数化模板生成器

### 3.1 设计原则

1. **参数独立于语义**：替换的是数量/编号/人名等"表面量"，不改任务结构。这样同模板的不同变体在认知难度上等价。
2. **生成即有效**：模板生成的每个变体都附带一个 `expected_*` 字典，artifact 核验器无需推理即可验证。
3. **变体可控**：通过 seed 复现相同变体，保证可对比性。

### 3.2 模板参数类型（t-* 字段）

| 参数类型 | 说明 | 示例 |
|---|---|---|
| `t-int(min,max)` | 随机整数 | 数据行数、SKU 数量 |
| `t-float(min,max,ndigits)` | 随机浮点 | 预算偏差率、金额 |
| `t-choice(list)` | 列表中随机选 | 人名库、部门名库 |
| `t-date(range_start,range_end)` | 区间内随机日期 | 任务开始/结束日 |
| `t-permute(items)` | 排列乱序 | 记录顺序、任务顺序 |
| `t-subset(items,k)` | 随机抽取 k 个 | 制造"预期遗漏"集合 |
| `t-offset(base,±delta)` | 基准量加减误差 | 制造"数值不一致" |

### 3.3 生成器代码

生成器实现：`paper/tasks/task_generator.py`（同目录下）。使用说明：

```bash
# 给已有15任务各生成3个变体，得45个JSON
.venv/bin/python paper/tasks/task_generator.py --variants 3 --out paper/tasks/data/generated/

# 用固定seed复现
.venv/bin/python paper/tasks/task_generator.py --seed 42 --variants 3
```

## 五、任务质量抽检方案（Phase 2 执行，这里先写规范）

- 抽检比例：≥10% 任务人工试做
- 抽检人：2 名独立标注者
- 记录指标：人工耗时、完成质量分（与自动分做一致性相关分析）
- 通过标准：人工分 vs 自动分 Spearman ρ ≥ 0.6，否则调整 L1/L2/L3 权重
