# TeamBench 种子任务设计（v0.1）

> Phase 0 / W2 产出
> 日期：2026-08-20
> 目的：3 个种子任务用于 p0-4 决策门验证"个体最优、团队次优"现象

---

## 一、设计原则

每个任务必须具备两种执行形态，用于计算**能力转化率**：

| 形态 | 定义 | 测量 |
|---|---|---|
| 团队模式 | N 个 subagent 分工协作（有通信开销） | 团队产出质量 Q_team + 协调开销 C |
| 个体模式 | 单个 agent 独立完成同一任务（无通信） | 个体产出质量 Q_single |

**能力转化率** = Q_team / (Σ Q_single_i)

- 转化率 < 1 → "个体最优、团队次优"现象复现（核心叙事成立）
- 转化率 > 1 → 团队有涌现增益

3 个任务按**任务耦合度**递增排列，覆盖分工收益从低到高的谱系：

| 任务 | 耦合度 | 分工价值 | 预期现象 |
|---|---|---|---|
| 种子1 协作周报 | 低 | 小（信息合并为主） | **团队次优**（通信开销 > 分工收益） |
| 种子2 项目风险预警 | 中 | 中（角色专长差异） | 边界区（验证转化率曲线） |
| 种子3 跨源数据核对 | 高 | 大（真并行 + 交叉验证） | 团队有优势 |

**决策门逻辑**：若种子1 出现团队次优、种子3 出现团队优势，则"协作税随耦合度递减"的核心曲线成立，论文卖点可复现。

---

## 二、种子任务 1：协作产出团队周报（低耦合）

### 任务描述
基于 5 名团队成员的本周工作记录（结构化片段），产出一份团队周报，要求：合并重复项、按主题归类、标注关键进展、识别跨成员依赖。

### 角色分工卡（团队模式，3 subagent）
| 角色 | 职责 | 输入 | 输出 |
|---|---|---|---|
| 收集员 collector | 读取 5 份成员记录，提取进展要点，去重 | 5 份成员记录 | 去重要点列表 |
| 分析师 analyst | 对要点按主题归类，标注跨成员依赖 | 收集员要点列表 | 主题归类 + 依赖图 |
| 撰写员 writer | 整合为结构化周报（含关键进展/风险/下周计划） | 分析师归类结果 | 周报文档 |

### 共享初始态
- 5 份成员工作记录（JSON，每人 3-5 条进展 + 1-2 条阻塞）
- 周报模板（含必要章节：本周进展/风险阻塞/下周计划）

### 交付物验收标准（artifact-based，状态核验）
1. 周报含全部 3 个必要章节（结构断言）
2. 去重准确率：原始去重要点数 vs 周报中出现要点数（数值断言）
3. 跨成员依赖识别数 ≥ 实际依赖数 * 0.8（数值断言）
4. 5 名成员全部被提及（覆盖断言）

### 个体基线版本
单个 agent 独立完成：读 5 份记录 → 去重 → 归类 → 识别依赖 → 写周报，全程无通信。

### 预期现象
分工价值小（去重归类是单线性工作），但团队模式有 3 次传递（收集→分析→撰写）的通信开销。
**预期转化率 < 1**，是"个体最优、团队次优"的核心复现点。

## 三、种子任务 2：项目进度同步与风险预警（中耦合）

### 任务描述
基于项目看板（含 8 个任务、3 个里程碑、2 条延期记录），产出风险预警报告：识别延期/阻塞风险、分析根因、给出 3 条可执行缓解建议。

### 角色分工卡（团队模式，3 subagent）
| 角色 | 职责 | 工具 | 输出 |
|---|---|---|---|
| 进度收集员 tracker | 读取看板，提取延期/阻塞任务 | 看板读取工具 | 风险任务清单 |
| 根因分析师 diagnoser | 对每个风险任务分析延期根因 | 历史记录检索 | 根因分析表 |
| 建议员 advisor | 基于根因生成可执行缓解建议 | 知识库 | 3 条缓解建议 |

### 共享初始态
- 项目看板 JSON（8 任务 + 3 里程碑 + 2 延期 + 历史变更记录）
- 风险报告模板

### 交付物验收标准
1. 报告含风险清单 + 根因分析 + 缓解建议三部分（结构断言）
2. 识别风险任务数 ≥ 实际风险任务数 * 0.8（数值断言）
3. 缓解建议可执行性评分（LLM-judge，子集双盲）：每条建议 ≥ 3/5 分
4. 根因命中实际延期原因的比例 ≥ 0.6（数值断言）

### 个体基线版本
单个 agent 串行完成：读看板 → 识别风险 → 分析根因 → 给建议。

### 预期现象
角色专长有差异（根因分析 vs 建议生成），分工有中等价值，但需 2 次传递。
**预期转化率 ≈ 1**，处于"协作税"曲线的拐点，用于界定收益边界。

## 四、种子任务 3：跨源数据核对（高耦合）

### 任务描述
有两个独立数据源（销售表 A 与库存表 B，各 ~50 条记录），需交叉核对：找出 A 有 B 无、B 有 A 无、数值不一致三类差异，产出核对报告。

### 角色分工卡（团队模式，2 subagent + 1 合并）
| 角色 | 职责 | 输入 | 输出 |
|---|---|---|---|
| A 源核对员 checker_a | 读表 A，提取键值，与 B 快照比对 | 表 A + B 快照 | A 视角差异 |
| B 源核对员 checker_b | 读表 B，提取键值，与 A 快照比对 | 表 B + A 快照 | B 视角差异 |
| 合并员 merger | 合并双向差异，去重，定优先级 | 双方差异 | 核对报告 |

### 共享初始态
- 表 A（CSV，~50 行，含 SKU/数量/日期）
- 表 B（CSV，~50 行，含 SKU/数量/日期，与 A 有 ~10 处差异）

### 交付物验收标准
1. A有B无差异识别准确率 = 正确识别数 / 实际数（数值断言）
2. B有A无差异识别准确率（数值断言）
3. 数值不一致识别准确率（数值断言）
4. 报告含三类差异且无重复（结构 + 去重断言）

### 个体基线版本
单个 agent 串行处理：读 A → 读 B → 逐条比对 → 产出报告。

### 预期现象
两源真并行（各 ~50 行独立处理），分工价值大，合并只需 1 次传递。
**预期转化率 > 1**，团队有涌现增益，对照种子1 形成曲线。

## 五、试跑计划（p0-4 决策门）

### 前置条件
- [ ] 配置 venv + 核心依赖（见 paper/infra/基础设施确认备忘.md）
- [ ] 配置真实 LLM API key（建议用中档模型控制成本）
- [ ] 准备 3 任务的输入数据（手工构造，每任务 1 份）

### 执行矩阵
| 任务 | 团队模式 | 个体模式 | 重复 |
|---|---|---|---|
| 种子1 | 3 subagent | 1 agent | 2 seeds |
| 种子2 | 3 subagent | 1 agent | 2 seeds |
| 种子3 | 2+1 subagent | 1 agent | 2 seeds |

共 ~18 runs（团队 3×2 + 个体 3×2，每模式每任务 2 seeds）。

### 决策门判定
- **现象复现**：种子1 转化率 < 1 且 种子3 转化率 > 1 → 核心曲线成立，推进 Phase 1
- **部分复现**：仅种子1 次优 → 调整种子3 耦合度（增加数据量放大并行收益）后重试
- **未复现**：两轮仍无次优现象 → 叙事转向"框架间协调开销差异"（数据必然支持）

### 成本预估
- 中档模型（如 GPT-4o-mini），每任务 ~5-15 次工具调用，单 run 预估 $0.1-0.5
- 18 runs 预估总成本 < $10
