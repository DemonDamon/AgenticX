## 0. 符号系统约定

| 符号 | 含义 |
|---|---|
| $T$ | 一个任务（task） |
| $M$ | 一个 LLM 模型 / 多 Agent 框架 |
| $s$ | 一个随机 seed（控制任务变体参数与 LLM 采样） |
| $\mathcal{A}_{\text{team}}$ | 团队执行模式：$N$ 个 subagent 分工协作，含通信 |
| $\mathcal{A}_{\text{single}}$ | 个体执行模式：单个 agent 独立完成同一任务，无通信 |
| $Q(\mathcal{A}, T, M, s)$ | 产出质量评分（0–1，artifact-based + LLM-judge） |
| $R(\mathcal{A}, T, M, s)$ | 一次执行的运行轨迹（event stream） |
| $N$ | 团队规模（subagent 数）。对于个体模式 $N=1$，团队模式 $N \geq 2$ |

## 1. 能力转化率 Capability Transfer Rate (CTR)

**定义**：团队模式的产出质量除以"相同总预算下"个体模式的产出质量。测量个体 $\rightarrow$ 团队的能力传递损耗（或涌现）。

### 1.1 基础定义（单任务单 seed）

$$
\mathrm{CTR}(T, M, s) \;=\; \frac{Q\big(\mathcal{A}_{\text{team}}, T, M, s\big)}{Q\big(\mathcal{A}_{\text{single}}, T, M, s\big)}
$$

### 1.2 聚合定义（多任务多 seed）

$$
\overline{\mathrm{CTR}}(\mathcal{T}, M) \;=\; \frac{1}{|\mathcal{T}| \cdot |\mathcal{S}|} \sum_{T \in \mathcal{T}} \sum_{s \in \mathcal{S}} \mathrm{CTR}(T, M, s)
$$

### 1.3 解读

| CTR | 解读 | 对应叙事 |
|---|---|---|
| $< 1$ | 团队产出 $<$ 个体产出 → 能力**损耗** | 个体最优、团队次优（"协作税 > 分工收益"） |
| $= 1$ | 团队产出 $=$ 个体产出 → 能力**持平** | 分工收益恰好抵消协作税 |
| $> 1$ | 团队产出 $>$ 个体产出 → 能力**涌现** | 分工收益 > 协作税（团队协作有正收益） |

### 1.4 设计动机

- 对标 Woolley 集体智能因子（collective intelligence factor $c$）：
  $c$ 测量"团队表现 / 个体表现的平均值"。CTR 同样取比值，但用于**人机混合团队**（成员全部是 LLM Agent）。
- 回答核心问题：花 $N$ 倍算力让多个 Agent 协作，到底合算不合算？
- 是整篇论文的**主指标**，所有主表格和主图都围绕 CTR 展开。

### 1.5 边界条件

- 分母为 0（$Q_{\text{single}} = 0$）：该 (T, s) 不计入 CTR 聚合。改为在附录报告 "Q_single=0 的任务数"。
- 分子分母都为 0：该样本直接丢弃，避免 0/0 不定式。

## 2. 协调开销 Coordination Overhead (CO)

**定义**：团队模式相比个体模式，多花的通信成本。分 4 个子维度。

### 2.1 Token 开销比 Token Ratio (TR)

$$
\mathrm{TR}(T, M, s) \;=\; \frac{\mathrm{Tokens}_{\text{team}}(T, M, s)}{\mathrm{Tokens}_{\text{single}}(T, M, s)}
$$

- $\mathrm{Tokens}_{\text{team}}$：团队模式所有 subagent 的 prompt + completion token 总和
- $\mathrm{Tokens}_{\text{single}}$：个体模式单 agent 的 token 总和
- 含义：**团队模式花了个体模式多少倍的 token**

### 2.2 通信轮次 Communication Rounds (CR)

从事件流统计：

$$
\mathrm{CR}(T, M, s) \;=\; \#\{r \in R(\mathcal{A}_{\text{team}}) \mid r.type = \text{ROUND\_START}\}
$$

- 含义：团队模式下所有 agent 的思考轮次总数（含 agent 内部的 thinking round，不只是 agent-to-agent 通信）
- 对应个体模式 CR=1（无分工，单 agent 一次跑完）。正式实验中也统计个体模式轮次作为对照。

### 2.3 消息冗余率 Message Redundancy (MR)

$$
\mathrm{MR}(T, M, s) \;=\; 1 - \frac{|\text{unique\_messages}(R)|}{|\text{all\_messages}(R)|}
$$

- 从 subagent 之间的通信内容（summary 传递、任务状态广播）统计去重率
- $=0$ 表示无重复通信，越高表示重复传递相同信息越多
- **注意**：p0-4 简化版不统计 MR，需要完整 AgentTeamManager 的 message bus 才能测量。Phase 1 基础设施完成后启用。

### 2.4 等待空闲比 Wait-Idle Ratio (WIR)

仅当团队模式支持并发时统计：

$$
\mathrm{WIR}(T, M, s) \;=\; \frac{\sum_{i=1}^{N} \text{idle\_time}_i}{N \cdot \text{total\_wall\_clock}}
$$

- idle_time_i = subagent i 在等待上游产出时 idle 的时间
- 含义：团队中有多少比例时间在"等人"。线性流水线式分工 WIR 高，真并行 WIR 低
- **注意**：p0-4 简化版串行执行，WIR 无意义。正式 runner 支持并发 subagent 时启用。

### 2.5 综合协调开销（聚合指标）

$$
\mathrm{CO}(T, M, s) \;=\; \langle \mathrm{TR},\; \mathrm{CR},\; \mathrm{MR},\; \mathrm{WIR} \rangle
$$

CO 是一个 4 维向量。在主结果表中报告全部 4 项；在散点图中用 TR（最直观）作为 CO 的一维代理。

## 3. 团队任务成功率 Team Mission Success (TMS)

**定义**：以最终 artifact 状态核验为一级判据的二元通过率。

$$
\mathrm{TMS}(T, M, s) \;=\; \mathbb{1}\Big[ \bigwedge_{c \in C_T} \text{assert}(c, \text{artifact}) \Big]
$$

- $C_T$：任务 $T$ 的 artifact 验收断言集合（如"周报含3个章节"、"A有B无的 SKU 全被识别"）
- $\mathbb{1}$：指示函数，所有断言都通过则 1，否则 0

### 3.1 与 CTR 的关系

- CTR 用连续质量分 $Q$，粒度更细（0.8 分和 0.79 分有差别）
- TMS 用二元 pass/fail，更保守（一个断言没通过就判失败）
- 两者都报告：TMS 给审稿人一个"硬通过率"的直觉，CTR 做定量分析

### 3.2 artifact 核验层级（避免 LLM-judge 偏见）

| 层级 | 判据 | 权重 | 示例 |
|---|---|---|---|
| L1 结构断言 | 正则/JSON schema 静态检查 | ≥50% | "含3个章节"、"输出含SKU列表"、"行数≥50" |
| L2 数值断言 | 可计算量的数值比较 | ≥30% | "风险任务识别数≥实际×0.8"、"qty误差≤3" |
| L3 LLM-judge | 语义/可执行性评分 | ≤20% | "缓解建议可执行性"、"归类合理性" |

**关键原则（吸取 p0-4 教训 + 经验ID 1347931）**：L1+L2 之和必须 ≥80%，LLM-judge 只能用于语义质量的最后 20%，不能作为主判据。否则 LLM-judge 偏见会污染结论。

## 4. 协议合规度 Protocol Compliance (PC)

**定义**：团队协作过程中遵守角色分工与协作协议的比例。仅对团队模式有意义。

### 4.1 三个子指标

| 子指标 | 公式 | 含义 |
|---|---|---|
| 角色越权率 Role Transgression (RT) | $\frac{\#\text{越权调用}}{\#\text{总工具调用}}$ | 角色 A 调用了只允许角色 B 使用的工具的比例 |
| 任务认领冲突率 Assignment Conflict (AC) | $\frac{\#\text{2+agent 同时认领}}{\#\text{总认领数}}$ | 多个 subagent 同时声明在做同一件事的比例 |
| 结果合并冲突率 Merge Conflict (MC) | $\frac{\#\text{artifact 合并冲突}}{\#\text{合并总数}}$ | 写共享 artifact 时发生 overwrite 冲突的比例 |

### 4.2 聚合

$$
\mathrm{PC}(T, M, s) \;=\; 1 - \frac{\mathrm{RT} + \mathrm{AC} + \mathrm{MC}}{3}
$$

PC ∈ [0, 1]，越高表示合规越好。

### 4.3 Phase 1 状态

PC 的测量依赖完整 AgentTeamManager 的：
- 工具白名单（role → allowed_tools 映射）
- 任务认领事件流
- artifact 合并事件

Phase 1 先定义好公式和 API 接口，Phase 2 runner 上线后再实际统计。p0-4 简化版 runner 不测量 PC。

## 5. 统计检验约定

| 比较 | 检验方法 | 显著性 | 效应量 |
|---|---|---|---|
| CTR(团队) vs CTR(个体) 的均值差异 | Welch's t-test（不假设等方差）或 Wilcoxon signed-rank（非参） | $p < 0.05$ | Cohen's d 或 Cliff's $\delta$ |
| 多模型间 CTR 差异 | 单因素 ANOVA + Tukey HSD 事后检验 | $p < 0.05$ | $\eta^2$ |
| 指标间相关性 | Pearson（线性）或 Spearman（秩） | $p < 0.05$ | $r$ / $\rho$ |
| TMS 二元通过率 | McNemar 检验（同任务两种模式配对） | $p < 0.05$ | — |

所有 $p$ 值做 Benjamini-Hochberg FDR 校正（多比较校正）。

## 6. 与现有基准的指标对应

| 基准 | 核心指标 | TeamBench 对应 | 关键差异 |
|---|---|---|---|
| TheAgentCompany | 任务成功率 / 部分完成率 / 步数 / $成本 | TMS / TR（$成本） | TAC 全是个体视角 |
| OSWorld 2.0 | 二元完成率 / 部分分 / 步数 | TMS / CR / CTR | OSW 全是个体视角，无 team 概念 |
| GAIA | Level1/2/3 通过率 | TMS（按耦合度分档） | GAIA 个体视角，无协作维度 |
| SWE-bench | resolved rate | TMS（软件工程子任务） | SWE 个体视角（虽有 PR 评审但非多 Agent 协作） |
| MultiAgentBench | 单任务得分 | CTR | MAB 虽有多 Agent，但指标仍按任务得分，无"个体→团队转化率"概念 |

## 7. 计算伪代码（实现参考）

```python
def compute_metrics(trajectory_team, trajectory_single, artifact_team, artifact_single, task):
    # Q: artifact-based scoring (L1+L2 ≥80% + LLM-judge ≤20%)
    Q_team = score_artifact(artifact_team, task, mode="team")
    Q_single = score_artifact(artifact_single, task, mode="single")

    # 1. CTR
    ctr = Q_team / max(Q_single, 1e-9) if Q_single > 0 else None

    # 2. CO (4-dim vector)
    tr = sum_tokens(trajectory_team) / max(sum_tokens(trajectory_single), 1)
    cr = count_events(trajectory_team, type="ROUND_START")
    cr_single = count_events(trajectory_single, type="ROUND_START")  # 可报
    mr = 1 - len(unique_messages(trajectory_team)) / max(len(all_messages(trajectory_team)), 1)
    wir = compute_wir(trajectory_team)  # None if serial

    # 3. TMS
    tms_team = all(assert_passes(c, artifact_team) for c in task["verification"]["asserts"])
    tms_single = all(assert_passes(c, artifact_single) for c in task["verification"]["asserts"])

    # 4. PC (team-only; None until runner supports it)
    rt = count_role_transgression(trajectory_team, task["roles_to_tools"])
    ac = count_assignment_conflicts(trajectory_team)
    mc = count_merge_conflicts(trajectory_team)
    pc = 1 - (rt + ac + mc) / 3

    return {
        "CTR": ctr, "Q_team": Q_team, "Q_single": Q_single,
        "TR": tr, "CR": cr, "CR_single": cr_single, "MR": mr, "WIR": wir,
        "TMS_team": tms_team, "TMS_single": tms_single,
        "PC": pc, "RT": rt, "AC": ac, "MC": mc,
    }
```
