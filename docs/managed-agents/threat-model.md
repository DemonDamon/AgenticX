# Managed Agents 威胁模型

本文覆盖托管智能体在 MA-00 冻结契约时必须正视的五类威胁。每类写明资产、威胁、控制措施，以及由哪一个子规划落地、用什么方式验证。MA-00 只实现 Manifest 拒绝明文密钥这一条控制，其余控制在后续子规划中实现，这里先把责任钉死。

## 1. 凭证泄露

**资产**：Manifest 中的 MCP 凭据、工具结果里的密钥、日志与事件库中的敏感文本、沙箱进程能读到的环境变量。

**威胁**：作者把 `headers` 或 `env` 写进 Manifest，密钥随版本 JSON 长期保存并可被读接口返回。工具结果把上游令牌回显到事件流。日志和事件落库后能被全文检索。沙箱启动时把真实密钥放进环境变量，进程或调试接口可以直接读到。

**控制措施**：Manifest 拒绝 `headers` 和 `env`（MA-00）。Vault 只写不读（MA-E06）。出站请求在命中允许主机时才注入真实密钥，沙箱内只放占位值（MA-A06）。事件与日志统一走 `redact_text`（MA-A06）。

**负责子规划与验证方式**：MA-00 用 fixture `mcp_server_secrets` 断言同时带 `headers` 与 `env` 的 server 被拒绝，错误字符串为 `secrets are not allowed in manifest`。MA-E06 验证 Vault 写入接口不提供明文读取。MA-A06 验证沙箱 `env` 只有占位值，并对事件历史与日志做检索，确认密钥原文不出现。

MA-E06 落地：凭证以两层信封加密存储（DEK + 主密钥），读接口只返回 `has_secret` 等非敏感字段；运行时解析接口只服务 agent-runtime，校验会话引用关系，并对每次解析写 `audit_events`（`ma.vault.resolve`）。主密钥丢失 = 全部凭证不可解密，需重新登记。密钥最短 8 个字符，短于这个长度的值无法可靠脱敏。

MA-A06 落地：cloud 会话在每个回合开始时解析 Vault。`environment_variable` 进入命令沙箱时只有 `agxsec_` 加 32 位十六进制的占位值。明文只出现在框架自己发出的请求里：`web_fetch` 的每一跳 URL，以及 MCP 工具参数。替换还要求目标主机命中该凭证的 `allowed_hosts`，或者该凭证是 `unrestricted`。事件正文、预览帧和进程日志都按已知明文替换，替换结果是 `[REDACTED:标签]`。

残余风险：bash 里执行 `curl -H "Authorization: Bearer $KEY"` 时，发出去的仍是占位值。要在任意子进程里透明替换，需要终止 TLS 的出站代理，这一版不做。外部服务如果把密钥编码、截断或拆开后再回显，脱敏对不上原文。长度不足 8 的密钥不会被替换。

## 2. 跨会话访问

**资产**：会话工作目录、会话事件流、会话里引用的文件与工具输出。

**威胁**：一个会话的执行体读取另一个会话的工作目录，或调用方订阅、拉取不属于该会话的事件流，从而看到别人的提示、工具参数和文件内容。

**控制措施**：`session_boundary.foreign_session_denial` 拒绝访问其他会话的工作目录（MA-A04 / MA-E03）。事件读取和 SSE 按 tenant 与 session 鉴权，不接受只凭事件 id 的跨会话查询（MA-E03）。

**负责子规划与验证方式**：MA-A04 与 MA-E03 各准备一条跨会话路径访问用例，断言被拒绝且不返回目标会话的文件或事件。MA-E03 再用另一个租户、另一条会话的 PAT 请求 `GET /ma/v1/sessions/:id/events` 和 SSE，断言 404 或 403，响应体不含目标事件。

MA-A07 落地：记忆只落到挂载它的会话的工作目录；其他会话（包括其他用户）的文件工具受 `foreign_session_denial` 拒绝、命令沙箱看不到其他会话目录；控制面快照接口另行校验会话确实挂载了该记忆库。

## 3. 跨租户访问

**资产**：其他租户的 Agent、环境、会话和 WorkItem。

**威胁**：PAT 被拿到后调用不属于该租户的资源。Worker 在长轮询里领走其他租户的 Work，并在本机执行、回传事件。

**控制措施**：每个接口同时检查 PAT scope 和 token 上的 tenant，查询必须带 tenant 过滤（MA-E02 / MA-E03）。Worker 只能领取 `worker_keys` 命中的环境上的 Work（MA-A05 / MA-D01）。

**负责子规划与验证方式**：MA-E02 与 MA-E03 用租户 A 的 PAT 请求租户 B 的 Agent、环境和会话，断言不可见。MA-A05 与 MA-D01 用未列入目标环境 `worker_keys` 的设备去 `work/poll`，断言领不到该 Work，且 `ack` 其他租户的 work id 失败。

## 4. 出站滥用

**资产**：沙箱所在网络、内网服务、被允许带到特定主机的密钥。

**威胁**：云端沙箱访问内网地址或云元数据服务。`environment_variable` 类型的密钥被带到未授权主机，等于把凭证交给攻击者控制的端点。

**控制措施**：云端环境配置 `egress_allow_domains`。名单非空时，`web_fetch`（含每一次重定向）和 MCP 连接按主机拦截，不在名单内的请求失败并留下 `session.error`（`egress_blocked`）；bash 在这种环境下直接断网。名单为空则不额外限制。`environment_variable` 凭证带 `allowed_hosts`，只有出站主机命中时才把占位值替换成真实密钥（MA-A06）。

**负责子规划与验证方式**：MA-A06 从 `web_fetch` 请求名单外的地址（含重定向跳走），断言失败并留下 `session.error`。同一凭证分别请求 `allowed_hosts` 之内和之外的主机，只有命中的请求带上真实密钥。bash 在名单非空时没有网络；命令沙箱不可用时拒绝执行。

残余风险：bash 不能按域名选择性放行，只能在名单非空时整体断网。macOS 的 `deny network-outbound` 需要在目标机器上实测，单测只检查沙箱配置文本。

## 5. 经工具结果回流的提示注入

**资产**：后续工具调用权限、用户尚未确认的高危操作、模型即将发出的写操作。

**威胁**：MCP 或网页工具返回的内容里夹带指令，诱导模型接着调用高危工具，把不可信文本变成新的工具参数。

**控制措施**：工具权限使用 `always_ask`，敏感工具必须等 `user.tool_confirmation`（MA-A03）。企业 deny 策略优先于 Manifest 的 allow（MA-A03）。合规网关对模型响应通道做评估（现有网关能力）。

**负责子规划与验证方式**：MA-A03 构造一次工具结果，其中包含继续调用高危工具的文本，断言该工具仍停在 `requires_action`，不会因为结果文本而自动执行。企业策略设为 deny 时，即使 Manifest 写了 `always_allow` 也不得执行。网关响应通道沿用现有策略评估，命中时与普通模型回复区分开。

记忆库会沉淀不可信内容：被提示注入诱导写入的文本会在后续会话作为记忆读回。共享知识应以 read_only 挂载；read_only 由不回写保证，权限钩子与文件权限只用于让模型尽早得知。
