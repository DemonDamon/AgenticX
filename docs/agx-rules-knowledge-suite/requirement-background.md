## 一、项目定位

客户拟交付一套**集知识库、规则库与智能引擎于一体的辅助开发工具集**，为上层应用提供标准化的知识检索、规则治理与任务调度能力。三大核心能力：

1. **自然语言规则智能生成**：从自然语言意图到可执行规则的自动化构建、可视化确认与执行编排；
2. **本体建模与知识融合**：基于本体论对多源异构数据统一建模、抽取、融合与版本治理，形成标准化知识检索与证据集；
3. **设备作业知识智能体**：自然语言意图解析与多源知识检索融合，支撑对话式查询、作业前知识提示、历史经验提示与案例辅助决策。

协同关系：知识库提供语义校验基座，智能引擎提供编译中枢，规则库提供策略资产，支撑上层应用自动化运行。

## 二、三大功能域（子模块级）

### 域1：自然语言规则智能生成

| 子模块 | 能力要点 |
|---|---|
| 自然语言交互与语义解析 | 日常运维语言录入规则需求；规范化、术语识别、多轮交互；意图识别（规则创建 / 修改 / 查询 / 测试执行）；关键要素抽取（业务对象、触发条件、比较关系、阈值、时间范围、执行动作、通知方式）；结合数据模型 / 专业词典 / 元数据做歧义校核与候选项确认 |
| 规则结构化与自动生成 | 按「数据对象—触发条件—判断逻辑—执行动作—结果反馈」结构组织规则；对象 / 数据项 / 动作映射至统一数据模型、OpenAPI 服务或已注册工具；生成引擎可执行的规则描述、任务流程或配置；语法、参数、类型、接口可用性、权限校验 |
| 规则确认与交互管理 | 结构化文本 / 流程视图可视化确认；缺失、冲突、高风险信息明确提示；自然语言或前端交互修改后重新校验；提交规则库并记录操作与版本关联 |
| 智能引擎集成与二次开发 | 按既有智能引擎规范完成接口适配与工具注册；规则 → 任务描述 → 步骤拆解 → 依赖配置 → 服务调用编排；执行状态（同步 / 解析 / 排队 / 执行中 / 完成 / 异常）回传；超时、失败重试、终止、人工处理；调用日志 |
| 规则库可视化与前端展示 | 多条件查询规则与启用 / 停用 / 测试 / 删除操作；执行流程可视化（触发条件、判断节点、执行步骤、分支走向、执行进度与异常位置）；受控代码片段 / 配置查看（语法高亮）、最新与历史执行结果追溯 |

### 域2：本体建模与知识融合

| 子模块 | 能力要点 |
|---|---|
| 知识资源接入 | 资产台账（接口 / 视图 / 文件）、业务数据（量测、告警、巡检、作业工单）、文档资料（规程规范、说明书、检修试验报告、缺陷案例，保留章节条款表格结构，**不采用无业务语义的固定长度切片**）；跨系统对象主索引与原始 ↔ 统一标识映射 |
| 知识建模 | 以资产、组织、岗位等核心对象为中心的本体建模；包含 / 隶属 / 安装 / 连接 / 管理 / 测量 / 空间位置等关系模型；知识对象档案聚合；图数据库（属性图、图遍历、基本推理） |
| 知识抽取与融合 | 实体 / 属性 / 关系抽取并保留原始上下文；按统一标识、别名、组织、位置做实体链接与主索引挂载；重复识别、来源优先级冲突处理、人工审核留痕；增量更新与变更追溯（避免全量重复加工） |
| 对象中心精准检索 | 对象识别与查询理解（编码 / 名称 / 别名 / 上下文消歧）；结构化查询 + 关系检索 + 语义向量检索结合；以对象为中心聚合证据（台账、状态、记录、条款），返回内容 + 数据时间 + 来源依据 |
| 大模型一键调用 | 知识查询封装为大模型 / 智能体可调用的标准工具；上下文按重要性、时间有效性、来源可信度组装；返回结构化数据 + 可读摘要 + 来源依据 + 缺失 / 冲突提示，**不得以推测内容替代真实知识** |
| 知识治理与运行保障 | 知识质量检查（标识关联、必填属性、关系完整性、重复、冲突、失效 → 问题清单）；草稿—待审核—已发布—已失效生命周期；对接既有用户 / 组织 / 数据权限体系；同步、加工、索引、调用监控与审计 |

### 域3：设备作业知识智能体

| 子模块 | 能力要点 |
|---|---|
| 对话式查询受理与对象定位 | 业务意图识别（档案查询 / 历史问题 / 案例比对 / 处置建议）；简称、习惯名称、片段式表达、连续追问；对象识别与消歧；条件理解转标准查询请求，组合调用多源知识 |
| 知识综合查询 | 档案与关联关系查询；时间范围内运行与业务记录查询（区分当前有效 / 历史 / 已失效）；以统一标识为中心跨源归并，避免同名 / 同类对象信息错混；未命中时明确反馈 |
| 作业前知识辅助 | 由作业工单识别涉及对象与工作内容，聚合直接相关的档案、历史问题、技术资料与案例（**避免返回无关通用信息**）；生成重点检查项；按「注意事项—形成原因—参考依据—建议确认方式」结构输出 |
| 历史问题与风险提示 | 历史缺陷、重复告警、巡检异常、检修记录摘要；重点问题识别（未闭环、重复发生、与本次工作部位相关、复查期限临近）；证据不足时标记「待确认」，**不得直接认定唯一原因** |
| 技术依据检索与适用性判断 | 按对象 / 部位 / 现象 / 作业内容检索规程条款；区分直接适用 / 条件适用 / 仅供参考 / 不适用；展示文档名称、章节、版本等来源信息；冲突时并列展示而非自行合并 |
| 缺陷案例比对与处置辅助 | 当前缺陷与历史案例多维比对（同 / 差异点与参考价值）；可能原因分类并逐项关联依据；生成处置方案草稿（目标、前置条件、步骤、风险、复查要求） |

另含非核心研究协助类工作（技术路线梳理、方法论沉淀、成果展示配合），及系统测试、部署实施、培训、交付物文档编制等交付服务。

## 四、对 AGX 的能力覆盖度摸底结论

以功能域人天测算为基准（能力域合计 610 人天，不含测试 / 部署 / 文档等交付服务）：

| 功能域 | 人天 | 主干覆盖度 | 已有底牌 | 主要缺口 |
|---|---|---|---|---|
| 自然语言规则智能生成 | 225 | ≈38% | `agenticx/core/workflow_engine.py`（状态机 + 条件路由）、`agenticx/flow/`、`agenticx/tools/`（工具注册 / OpenAPI 工具集 / 调用日志与重试）、`agenticx/runtime/confirm.py` 确认门控 | **「规则」不是一等公民实体**：规则 CRUD / 版本 / 启停 / 审核 / 审计 / 状态机全缺；NL → 结构化规则生成链路缺；规则库前端缺 |
| 本体建模与知识融合 | 210 | ≈57% | `agenticx/knowledge/graphers/`（schema 生成 / SPO 抽取含证据字段 / 图数据库导出 / 校验 / 社区发现）、`agenticx/retrieval/`（图 + 向量 + BM25 三路混合、QueryAnalysisAgent、reranker）、`retrieval/tools.py`（RAG-as-tools）、`data_suite/idmapping/`（主索引合并 + 冲突策略 + 快照回放） | 对象中心证据包聚合；检索结果系统性来源引用；知识对象生命周期状态机与质量清单；权限对接 |
| 设备作业知识智能体 | 175 | ≈55% | `agenticx/runtime/agent_runtime.py`（意图锚定 / 多轮 / 工具编排 / 循环检测 / 子智能体）、大结果持久化、`enterprise/apps/web-portal/` 对话界面（含引用展示） | 领域 prompt 包（项目定制）；跨源归并；通用消歧确认交互模式 |
| **合计** | **610** | **≈49%** | | **通用能力缺口 ≈190 人天**（不含领域层定制） |

**关键判断：**

1. 缺口 ≈190 人天中绝大多数是**通用产品能力缺口**，而非领域定制缺口——领域本体、术语词典、源系统适配器、作业 prompt 包本来就不应进主干；
2. 售前历史中「金融合规审计的规则审核」「集团数据画像的指标规则」与本项目「运维业务规则」是**同一个抽象**：自然语言 → 结构化规则 → 引擎编译执行 → 可视化追溯，目前散落在各项目重复建设；
3. 即使能力覆盖达到 100%，受客户栈约束，此类项目交付仍需 Java 侧落地——AGX 的价值是**能力基座 + 逻辑参考**，不改变单项目交付形态。

## 五、仓库边界（同 AGX Data Suite 的 A/B 分层）

- **A 层（进主干，≈150–190 人天）**：规则资产与规则引擎、检索证据与引用结构、知识对象生命周期与质量治理、消歧确认交互模式、图谱增量更新——全部以「配置 / 插件实例」表达通用语义，不认任何行业专名。
- **B 层（项目仓，不进主干）**：领域本体实例（资产 / 岗位 / 组织字典）、专业术语词典、台账 / 工单 / 告警源系统适配器、作业知识 prompt 包、客户栈工程适配（Java 微服务壳、等保合规落地）。

## 六、风险与待澄清（对规划的约束）

1. 客户侧「既有智能引擎」的接口规范与部署形态在售前阶段未提供——AGX 规则 → 工作流编译层必须做成**目标引擎可插拔**（编译到 AGX Flow 与编译到外部引擎规范是两个 backend）；
2. 效果类功能（规则生成、意图解析、知识摘要）验收标准未量化——产品化时需内置**量化评测基准**（规则生成准确率、消歧命中率、引用忠实度）；
3. 成果 IP 归属客户——复用 AGX 资产的项目只能以「框架层复用 + 业务层交付」模式参与，主干能力设计必须把「业务语义」全部外置为配置，保证交付代码不携带 AGX 业务实现。
