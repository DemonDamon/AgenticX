# AgenticX 规则与知识套件 · 产品操作手册

> 适用：管理台「规则治理 / 知识生命周期 / 消歧确认」验收与实施演示（脱敏，无客户名）  
> 环境：管理台默认地址 `http://127.0.0.1:3001`  
> 验证日期：2026-10-29（本地 E2E + 高清截图）  
> 样例数据：仅 **Brand-A** 合成标识，不含真实客户名

本手册按「打开哪里 → 做什么 → 看到什么」写，给产品与实施同学按步骤操作。不写引擎内部实现细节。

---

## 一、这份手册给谁看 / 能干什么

| 读者 | 用来做什么 |
|------|------------|
| 产品 / 实施 | 按页面走通 R1、K1、K2、R2 演示路径 |
| 验收同学 | 对照截图与清单，确认页面不是空白、状态能改、出处能看见 |

## 二、打开哪里

### 启动与登录

1. 确认管理台已启动（开发默认端口 **3001**）。
2. 浏览器打开：`http://127.0.0.1:3001/login`。
3. 输入管理员邮箱（本地种子一般为 `admin@agenticx.local`）和本机配置的管理员密码。
4. 点击「登录并进入控制台」。
5. 登录成功后应进入 Dashboard。

### 三个入口

登录后可用左侧导航，或直接打开下列地址：

| 入口 | 路径 | 左侧导航文案 |
|------|------|--------------|
| 规则治理（R1） | `/admin/rule-governance` | 规则治理 |
| 知识生命周期（K2） | `/admin/knowledge-lifecycle` | 知识生命周期 |
| 消歧确认（R2） | `/admin/disambiguation` | 消歧确认 |

完整示例：`http://127.0.0.1:3001/admin/rule-governance`。

### 预期

- 三个页面都能打开，标题分别为「规则治理」「知识生命周期」「消歧确认」。
- 列表区短暂显示「加载…」后应出现表格行；长时间空白或一直加载，先确认管理台与登录态。

## 三、R1 规则治理

### 3.1 打开列表

1. 打开 **规则治理**（`/admin/rule-governance`）。
2. 等待「加载规则中…」消失。
3. 左侧「规则列表」出现表格：ID、名称、状态、启用。

### 预期

- 至少有一行 Brand-A 样例规则。
- 页脚提示「已从 API 加载」为正常；若显示「本地种子数据」，说明 API 暂不可用，仍可看样例布局。

![规则列表卡片](e2e-shots/01-rule-governance-list.png)

*图：规则列表卡片（元素截图，与详情/执行区分开）*

### 3.2 看详情

1. 在表格中点击某一行（样例可用 Brand-A 规则）。
2. 右侧「规则详情」刷新。
3. 核对：ID、名称、状态、启用、对象等字段与选中行一致。

![规则详情面板](e2e-shots/02-rule-governance-detail.png)

*图：选中 Brand-A 样例后的详情卡片（元素截图）*

### 3.3 看最近执行

1. 保持某条规则选中。
2. 在详情区找到「最近执行」。
3. 有种子执行数据时，应看到若干条记录（验收要求：Brand-A 样例须非空；空列表视为未种子）。

![最近执行记录](e2e-shots/03-rule-governance-executions.png)

*图：已种子时的最近执行列表（元素截图）*

### 验收标准

列表有行、详情随点击切换、执行区有内容或明确空态——不是空白页。

## 四、K1 引用与出处

K1 **没有**单独的管理台页面。验收放在对话或检索结果里：答案旁边应能看见「出处」，而不是只有一段无来源的话。

### 你应该看到什么

在门户对话 / 检索结果中，围绕某个对象（样例可用 Brand-A 实体）的答复旁，应出现：

1. **出处列表**  
   每条有短标签 + 摘录（例如台账属性、关联记录、文档条款一类说明）。可再展开看到来源标识、置信度等。
2. **冲突提示（如有）**  
   同一属性来自不同来源且取值不一致时，应并列标出冲突，而不是悄悄合并成一个值。
3. **缺失提示（如有）**  
   证据不齐时给出软提示（例如缺某类必填属性），不要假装证据齐全。

### 操作建议（演示）

1. 打开门户对话或带检索结果的页面（管理台默认仍是 `http://127.0.0.1:3001`；门户入口以本机部署为准）。
2. 查询一个 Brand-A 样例对象。
3. 在结果区找：出处条目、冲突区（若有）、缺失提示（若有）。

### 验收标准

- 有出处条目（标签 + 摘录），不是「裸答案」。
- 有冲突时能看见冲突，而不是被系统自行抹平。
- 证据不足时有提示，而不是用推测顶替。

（字段含义与展示约定见同目录 `citation-ui-contract.md`；本手册只要求页面上人眼能核对上述三点。）

## 五、K2 知识生命周期

### 5.1 打开对象列表

1. 打开 **知识生命周期**（`/admin/knowledge-lifecycle`）。
2. 等待「加载知识对象中…」消失。
3. 「知识对象」表格出现：ID、类型、状态、版本。

### 预期

- 至少有 Brand-A 合成对象（如泵 / 站点一类样例 ID）。
- 状态取值对应：`draft`（草稿）→ `pending_review`（待审）→ `published`（已发布）→ `retired`（已退役）。

![知识对象列表](e2e-shots/04-knowledge-lifecycle-list.png)

*图：知识对象列表卡片（元素截图）*

### 5.2 状态流转

1. 点击一行对象，右侧打开「对象详情」。
2. 看当前状态（如 `draft`）与版本号。
3. 在详情区点击允许的下一状态按钮（按钮文案形如 `→ pending_review`）。
4. 成功后应提示状态已更新；详情与列表中的状态同步变化。
5. 下方「变更追溯」应多出一条记录（时间 · 动作 · 旧状态→新状态 · 操作者）。

常见可点路径（以页面按钮为准）：

| 当前 | 可转到 |
|------|--------|
| 草稿 `draft` | 待审 / 已退役 |
| 待审 `pending_review` | 已发布 / 回草稿 / 已退役 |
| 已发布 `published` | 已退役 / 回草稿 |
| 已退役 `retired` | 回草稿 |

![对象详情与流转](e2e-shots/05-knowledge-lifecycle-detail.png)

*图：对象详情与可执行状态流转（元素截图）*

### 5.3 跑质量检查、看问题

1. 页面顶部点击 **运行质量检查**。
2. 等待成功提示「质量检查完成」。
3. 再选中相关对象，看「质量问题」列表：编码、严重级别、状态、说明。
4. 对未关闭问题可点 **标记已解决**；解决后状态应变为已解决。

![质量问题面板](e2e-shots/06-knowledge-lifecycle-issues.png)

*图：质量检查后的问题列表（元素截图，须非空）*

### 验收标准

列表有对象；状态按钮能改状态且变更追溯有记录；跑质量检查后问题区有内容或明确空态。

## 六、R2 消歧确认

打开 **消歧确认**（`/admin/disambiguation`）。左侧是会话列表，右侧是「选择面板」。

三种模式各一句：

| 模式 | 何时用 | 你做什么 |
|------|--------|----------|
| 候选选择 | 多个候选对象 / 标签，需要人选一个或几个 | 勾选候选 → 提交答复 |
| 信息补充 | 缺一段必填说明 | 在自由文本框填写 → 提交答复 |
| 冲突裁决 | 同一项有多套冲突取值 | 选定采纳项（及必要时补充说明）→ 提交答复 |

页面若无样例，可点 **重置 Brand-A 样例** 再演示。

### 6.1 候选选择

1. 在会话列表点开「候选选择」类会话。
2. 右侧模式显示「候选选择」。
3. 勾选一个或多个候选。
4. 点击 **提交答复**。
5. 应提示答复已应用；待处理请求减少或会话完成。

![候选选择模式](e2e-shots/07-disambiguation-candidate-select.png)

*图：候选选择面板*

### 6.2 信息补充

1. 打开「信息补充」类会话。
2. 在「自由文本」框填写缺失信息（样例文案即可）。
3. 点击 **提交答复**。
4. 应提示成功；已解析槽位 / 已解决轨迹有更新。

![信息补充模式](e2e-shots/08-disambiguation-info-supplement.png)

*图：信息补充面板*

### 6.3 冲突裁决

1. 打开「冲突裁决」类会话。
2. 右侧展示冲突项（多来源取值并列）。
3. 按页面选项选定要采纳的一方（必要时勾选候选编码）。
4. 点击 **提交答复**（或 **取消会话** 结束本轮）。
5. 应提示成功或已取消；冲突不再处于待处理。

![冲突裁决模式](e2e-shots/09-disambiguation-conflict-resolve.png)

*图：冲突裁决面板*

### 验收标准

三种模式都能打开对应面板；提交或取消后有明确反馈，不是点了没反应。
