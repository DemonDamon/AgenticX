# 项目背景与需求摘要（脱敏版）

> **脱敏说明**：本文为某设施管理垂类商机（下称"本项目"）的背景摘要，甲方为某大型会展场馆运营方的设备设施管理部门。已按脱敏规范移除甲方名称、项目专名、供应商与内部人员姓名，规模数字做取整模糊。原始客户材料不入库。配套材料：[02-需求沟通纪要-脱敏.md](./02-需求沟通纪要-脱敏.md)。

## 1. 项目概述

- **甲方**：某大型会展场馆运营方的设备设施管理部门，负责全部展馆区设备设施的运行维护，外包维保队伍约每两年重新招标，人员流动大、经验难沉淀。
- **项目**：智慧设施管理系统——甲方单独立项（与数据中台分开预算），定位为场馆设备设施的"大脑"层。
- **核心痛点**：
  1. 无信息化基础：巡检靠纸质、台账靠 Excel；
  2. 事后维修为主：无数据支撑的"修/换"决策，要么过度更换、要么等坏再修；
  3. 设备定位靠图纸和个人记忆，人走经验丢；
  4. 知识不沉淀，维保外包更替后经验清零。

## 2. 系统边界（三层）

| 层 | 内容 | 归属 |
|---|---|---|
| 底层 | 20 余个子系统（楼控 BA、冷源、能耗、消防、给排水、电梯、安防等）+ 物联底座（物联网卡直连新装传感器，不经过子系统防火墙策略） | 甲方既有/他建 |
| 中层 | 数据中台（已有 vendor 建设部分接入，扩容归综合管理部门，**不在本项目盘内**） | 他建 |
| 上层 | 智慧设施管理平台：设备运行监测、预测性维护、能耗优化、知识管理、工单闭环、可视化 | **本项目交付** |

新装传感器量级约百个起步、逐年扩容（屋面天沟液位计 40+、照度 <10、会议室温度若干）；接入走甲方物联底座，我方不建 IoT 接入面。

## 3. 业务闭环与四大 AI 优化方向

闭环：**感知采集 → 数字建档 → 评估诊断 → 预测预警 → 决策建议 → 工单执行 → 反馈优化**。

1. **预测性维护**：设备健康画像（磨合期/稳定运行期/红灯期，红黄绿三态），全生命周期动态评估，支持剩余寿命（RUL）预判；
2. **能耗优化**：不止于数据报表，要做根因分析，关联展会计划、客流、天气等多元异构数据；
3. **运行逻辑优化**：启停顺序、联锁、备用轮换、负载分配；
4. **运维流程优化**：派单规则、人员配置、备件、巡检频次。

## 4. 甲方技术倾向（关键信号）

- 明确**不要固定工作流，要 Agent 自主编排**；
- 做完一个场景**固化为 skill / MCP 工具形态**，复制到下一个专业；
- 要**训练自己的垂类小模型与 Agent**（按空调、配电、电梯、给排水等专业分垂类），工程师在回路持续训练（PDCA）；
- 数据治理从现在往后采集，历史数据不足 → 算法需**小样本冷启动**能力；
- 工单全流程移动化闭环：扫码 → 三维模型/数字档案/维修指导 → 关单后"预测 vs 实际"比对沉淀案例。

以上与 AGX 的 runtime / skills / learning / trainer / evaluation 产品理念完全同构。

## 5. 设备档案数据画像（脱敏）

- **规模**：4.5 万余条设备记录，近 20 个专业系统；
- **Top 分布**（取整）：电气 1.2 万、照明 8 千余、中控智能 7 千余、暖通 5 千余、消防 3 千余、给排水 3 千余、通讯视听 2 千余、安防 1 千余，其余为电梯、楼控、广播、能耗采集等长尾；
- **Schema（8 列）**：标题（含分区+设备编码）、设备名称、型号/规格、专业系统、品牌、生产厂商、制造厂/供应商、安装日期；
- **数据质量**：厂商/品牌字段脏（存在错别字、名称不规范），编码规则不统一，清洗与实体对齐是数字建档的前置工作。

## 6. 评审关注的 7 大议题

1. **与既有数据中台的关系**：扩容还是重建（我方边界：只做对接）；
2. **物联网数据回写预警**：分析结果回传子系统侧预警（首期不下发控制指令）；
3. **与运营指挥中心的关系**：定制页面以 iframe 嵌入，角色分层视图（领导/基层管理/专业工程师）；
4. **预测性维护与健康评估路径**：RUL 冷启动策略是技术标核心议题；
5. **AI 落地路径**：Agent+大模型如何落地、可解释性、人在回路、安全边界；
6. **可视化实施**：2D/3D/BIM，图纸不全的现实约束；
7. **系统集成**：与既有工单系统对接，幂等、重试、补偿。
