## 一、项目定位

集团级用户数据资产与应用基础设施建设项目，以「360 用户画像面板」和「数据中台主实体关联能力」为核心交付，把分散的用户数据与研究成果整合为「用户识别 → 用户洞察 → 策略落地」的标准化工作机制，为品牌 / 细分市场 / 产品线 / 配置版本四层级（L1–L4）经营决策提供统一口径、可信可复用的画像数据支撑。

两大核心诉求：

1. **统一口径的可信群体画像**（360 用户画像面板）
2. **可关联个体分析的主实体画像**（数据中台人–资产标签宽表）

## 二、现状痛点（客户自述）

- **跨产品线人–资产关系画像获取壁垒高**：无统一数据出口，单一产品线依赖业务团队支持，多产品线横向拉通需分别取数。
- **缺统一口径**：L3 产品线层 / L4 配置层大数据画像缺乏集团级统一口径数据源。
- **缺可信渠道**：静态标签（人口属性等）数据源多而杂，存在年龄异常、家庭结构互相矛盾、多条记录冲突等质量问题，最可信数据源需治理后才能确定。
- **首次拉取周期长**：原始端侧信号需多部门确认含义与上报链路，需从头加工清洗；部分指标缺信号或未采集。
- **埋点偏行为记录**：缺乏性能与体验的直接度量，难以归因。
- **多渠道数据难关联**：调研 / APP / CDP / 门店与订单系统 / 端侧平台难以统一关联（部分品牌 OneID 不成熟、部分品牌缺 OneID）；销售订单等数据无常态化获取通道，权限散、申请慢。

## 三、六大交付域

1. **360 用户画像面板**：L1 品牌 / L2 细分市场 / L3 产品线 / L4 配置四层视图；支持立项前 vs 上市后、不同产品线、不同配置版本对比分析与下钻。
2. **权限管理**：RBAC、字段级脱敏、页面水印、操作审计；对接客户统一认证与多层权限控制体系（零信任网关 / 报表权限 / 数据权限）。
3. **数据标签体系**：标签 3 级分层、百级以上标签目标规模，每个标签带四要素（业务定义、计算逻辑、更新频率、责任人）；首期先上线数十个核心标签跑通链路再滚动扩展；支持人群圈选。
4. **数据治理**：字段级数据字典与元数据、四类清洗规则（标准化 / 去重合并 / 补全推导 / 异常剔除）、S/A/B/C 可信度分级（S 基准事实 / A 统计事实 / B 代理推断带置信标识 / C 待治理冻结）、多源比对仲裁（优先级：权威证件类 > 主档案 > 注册信息）、数据质量看板（关键字段完整率、准确率、T+1 及时率、异常留痕率等按日更新，阈值级门槛由项目约定）。
5. **数据入湖 ETL 与 OneID**：十余个业务系统数据盘点与入湖；OneID 打通（one_id × 资产标识 × 人–资产关系粒度，过渡期可用手机号等弱关联字段）；T+1 快照、画像可回放。
6. **数据资产平台迭代**：客户已有数据资产平台的功能与血缘梳理、归档销毁策略、迭代优化。

## 五、客户环境（技术架构要点）

- **算力在客户侧**：双云大数据平台（流批一体：Kafka / Flink / Spark / HDFS / HBase / Redis；OLAP：ClickHouse / Hive / Impala），另有 CDP 平台双云部署、专线对接。应用层常见 Spring Boot + Vue 栈，认证含 OAuth2 / Spring Security 一类方案。
- **等保三级**要求；数据安全四维度设计：应用开发配置安全（SQL 参数化、本地不留数据）、应用访问安全（统一认证与会话加密）、系统访问安全（多层权限控制 + 页面水印）、数据存储与网络隔离（堡垒机 + IP 白名单、多副本备份、内网隔离、防火墙）。
- **分工边界**：各数据源 Owner 负责采集、打通与质量维护；客户数字化部门负责入湖数据的基础治理、专项治理、安全权限与算力支持；业务研究部门负责问题定义、场景应用与反馈。

## 六、行业对标

某头部企业营销与服务域数据治理公开实践：以「数据五可」为目标（可见 → 可理解 → 可用 → 可管 → 可决策），方法论（OneData 一类体系）+ 研发治理一体化工具平台 + OneID 与客户主数据 + 统一指标字典 + 非结构化资产化 + 全链路质量监控 + 分类分级 / 动态脱敏 / 审计合规 + 敏捷自助消费 + 面向 AI 的数据底座。客户以此为主要参照系，预期交付是**数据治理方法论 + 工具落地**，而非单纯报表。

## 七、对 AGX 的启示

1. 六域中多数为 AGX 当时空白（连接器能力偏窄且只读、无 BI 看板框架、无标签圈选、无数据治理、无资产平台）——催生 AGX Data Suite 规划（见关联规划文档）。
2. 客户环境决定了「算力下推、数据不出域」的架构边界，通用能力必须以此为前提。
3. 治理方法论（分级 / 清洗规则 / 质量指标 / 标签四要素 / 先窄后宽）具有跨客户通用性，值得内置为产品推荐实践。
4. **仓库边界**：约 80–90% 可复用能力进 AgenticX（A 层）；行业宽表主题、字段字典实例、标签清单、看板业务指标、系统对接与权限对接等约 10–20% 定制放在独立项目仓（B 层）。
