## 1. 为什么做

企业数据智能类交付里，AGX 在连接、作业编排、OneID/ID-Mapping 等通用能力上存在硬缺口。规划原则是 **A（通用能力进主干）+ B（项目配置与少量适配）**，避免项目专属逻辑渗入引擎。

P0 硬门槛：**连上通道 → 声明作业 → 跑通可配置 ID-Mapping（含快照回放）**，且不替客户建湖仓；算力仍在客户侧。

## 4. 作业与 ID-Mapping 样例（可直接对照代码）

### 4.1 样例作业 `sample_oneid_job`

```yaml
name: sample_oneid_job
schedule: "0 2 * * *"
nodes:
  - id: extract_src
    type: extract
    channel: src
    statement: "SELECT * FROM raw_users"
  - id: clean_nulls
    type: clean
    drop_null: ["id"]
  - id: transform_idmap
    type: transform
    idmap: default
  - id: load_dst
    type: load
    channel: dst
    table: users_out
    grant_id: g_load
  - id: snap
    type: snapshot
    target: memory
```

### 4.2 ID-Mapping profile

```yaml
name: default
id_types:
  - name: phone
    priority: 10
  - name: crm_id
    priority: 20
merge:
  priority: [crm_id, phone]
  on_conflict: prefer_priority
```

验收语义：同 phone 可合并为同一 `subject_id`；冲突按优先级策略处理；快照可 replay。
