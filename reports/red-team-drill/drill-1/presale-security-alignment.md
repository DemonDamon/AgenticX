## 一、对照框架：模型、数据、应用、访问全链路一体化管控

行业共识（大模型时代的安全治理）：AI 安全不是单点防御，而是**事前测评准入、事中风控拦截、事后审计处置**的全链路一体化。下表为 AgenticX 逐项对答：

| 阶段 | 框架要求 | AgenticX 落点 | 证据（可验证） |
|---|---|---|---|
| 事前 | 模型安全测评 | `agx security-eval` 红队评测线：版本化攻击语料（guard 规则反向生成 + 公开越狱手法种子）× 模型矩阵 → 安全记分卡（md+json 落盘），安全分与模型拒绝率、规则栈拦截率分列 | `reports/security-eval/real-matrix-1/`（双模型真实记分卡：安全分 76/A 级与 69/A 级，42 条攻击语料） |
| 事前 | 风险准入（评审制） | 模型启用接**准入门槛**：低于安全阈值阻断启用，例外须记录在案的 override 留痕 | `enterprise/apps/admin-console` 准入门槛（评测分驱动的启用阻断 + override 审计） |
| 事前 | 数据脱敏 | 网关计量落库前脱敏（密钥/邮箱/手机号）+ Handoff 外发 redaction + PII 输入不进共享缓存 | `enterprise/SECURITY.md` 3.5 数据最小化原则 |
| 事中 | 大模型防火墙 | 企业网关策略引擎：关键词/正则/PII/Prompt 四类规则，请求/响应/流式三向拦截（90001/90002），租户级规则包快照热加载 | 网关策略引擎（拦截即落审计链，先审计后拦截） |
| 事中 | 提示词风控 | **主链路 SafetyLayer 统一贯通**：agent 循环工具结果默认过四级管线（截断→泄露 redact→策略→注入中和），输入校验六规则前置（shell 注入/路径穿越/系统文件/命令替换/SQL/SSRF），全量安全事件桥接企业审计 | SP6 实测：工具输出注入 3 条、凭据外泄 3 条全部拦截（见拦截矩阵 A2/A3） |

| 事中 | 内容审核 | 合规规则包（涉政/暴恐/色情/广告，租户可配数据包）+ 第三方内容安全 API 可插拔适配（通用 JSON 契约）；provider 故障走降级档：本地规则兜底 + CRITICAL 告警，不静默放行；strict 租户选装 fail-closed | SP6 实测：合成合规违规词 1 条 → 90001 阻断 + 审计带类别 + 告警送达（见拦截矩阵 A11） |
| 事后 | 审计溯源 | 防篡改审计链：append-only + blake2b checksum 跨行链 + 网关 7×24 周期自检 + 管理后台链校验/下钻；trace_id 贯穿策略命中/告警/处置 | SP6 实测：篡改审计链 1 条 → 校验断裂检出 + CRITICAL 告警送达（见拦截矩阵 A10） |
| 事后 | 风险告警 | AlertDispatcher 分级分发（复用规则 severity）：通用 webhook + 飞书群机器人，去重窗口 + 通道级限流防风暴，分发动作本身落审计 | 网关告警分发通道（租户级配置） |

## 三、工程纪律（可作为客户安全团队尽调的对答点）

1. **先审计后动作**：拦截、放行、处置全部先落审计链再执行，禁止静默行为。
2. **规则是数据**：越狱检测规则、合规规则包、攻击语料、准入阈值全部数据化配置、可热更新。
3. **fail-closed 仅限凭据类**：密钥/凭据不确定性即拦截；内容审核外部依赖故障走降级 + CRITICAL 告警。
4. **纵深防御**：主链路 SafetyLayer 与网关策略引擎双独立拦截面，攻破一层不等于穿透。
5. **审计防篡改**：checksum 链 + 周期自检 + 管理后台校验三重保障，链断裂即 CRITICAL 告警。
6. **演练常态化**：攻防演练纳入事件响应 SOP 季度重跑，拦截矩阵报告版本化落盘、持续对齐最新攻击手法。
