# 复刻算法与合成数据实验

## 复刻

- 能 import 的直接 import（token 估算、随机抽卡这类纯函数）。
- 不能 import 的原样抄，函数开头注释写 `复刻自 path/to/file.py:L5048-5084`。
- 复刻完先自检：用两种写法（快速估算、逐字符统计）算同一批样本，结果要一致。

## 合成数据

| 材料 | 怎么造 | 必须标注 |
|---|---|---|
| 被检索的内容（例如制度章节） | 三档长度分布：全短章 1–5K 字、混合（60% 短章、30% 长章、10% 整篇）、整篇为主 | 长度分布是设定值 |
| 查询（例如问题点） | 按数量梯度：1、2、3、5、8、10、15、20 | 数量梯度是人为选的 |
| 金标准 | 在合成内容里预埋「关键条款」，事后算保留率 | 关键条款是人为指定的 |

合成数据只验证算法行为。绝对值（多少 K 会超）不能当承诺；相对关系（谁是主因、哪种手段有效）可信。

## 实验矩阵

| 实验 | 回答什么问题 | 输出 |
|---|---|---|
| 容量 | 什么时候超 | 问题点数 × 每点选卡数的输入 token 中位数表，标出超窗 |
| 缓解 | 哪种手段有用 | 每种手段的单次峰值、峰值降到现状的比例、调用次数、关键条款保留率 |
| 出口校验 | 缺陷能不能拦住 | 每类篡改的检出数和试验数，干净样本的误报数 |
| 可复现性 | 同一输入两次结果是否一样 | 两次选中结果完全一致的比例，平均重合度 |

缓解实验一定要同时看峰值和保留率。只看峰值会选到「截断」，而截断会丢关键内容。

每个实验至少跑 30 次取均值。检出类实验每类至少 20 次，干净样本至少 50 次。

## 取整

表格里统一用一种取整方式（舍去尾数到千位，或四舍五入），核对脚本用同一种。

上下界的结论要逐个数字对。没超过窗口的不要写成「超」，写成「逼近」并给出数。

## 数据落盘

每组实验的原始结果写入 `results.json`，结构见 `decision-gate.md`。报告和文档里的每个数字都要能回指这份文件；改任何数字先改结果文件再改文档，两边取整方式一致。

## 报告模板

```text
# <项目>「<功能>」对齐真实代码的校准报告

> 数据说明：生产库可得还是不可得，合成的是哪些，算法复刻自哪里
> 复现：cd <dir> && python3 <script>

## 1. 项目定位（含证据）
## 2. 真实链路（链路表）
## 3. 问题点（贴代码片段，带行号）
## 4. 实验结果（容量 / 缓解 / 出口校验 / 可复现性）
## 5. 对文档的校准清单（现状要改什么 / 方案要改什么）
## 6. 到现场多长时间能换成真实数据
## 7. 边界
```

如果这份报告推翻了之前的一份，在报告开头写明取代哪一份、为什么。

## 现场取数

SQL 要能在现场直接执行，所以写之前在代码里核对三样：

- 表名。有些表是原生 SQL 建的，不在 ORM 模型里，要搜 SQL 字符串才能找到。
- 字段名。
- 数据库方言。`JSON_LENGTH` 是 MySQL 的写法，PostgreSQL 用 `json_array_length`。

别名用英文，避免标识符的字符集问题。
