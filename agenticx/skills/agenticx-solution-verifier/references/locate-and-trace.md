# 定位项目与还原链路

## 全组织搜索

先列出候选仓库，再逐个在所有分支上搜。业务词用多个 `-e` 连成一组，一次搜完。

```bash
# 单个仓库、所有本地分支和远程分支
git -C <repo> for-each-ref --format='%(refname)' refs/heads refs/remotes \
  | xargs git -C <repo> grep -n -I -e '一键生成' -e '圈选' -e '证据卡片'

# 只看命中了哪些文件
git -C <repo> grep -l -I -e '一键生成' $(git -C <repo> for-each-ref --format='%(refname)' refs/heads) | sort -u
```

仓库多的时候用 Agent 并行搜，每个 Agent 只报「命中文件、分支、命中行」。

判读：

| 命中位置 | 说明什么 |
|---|---|
| 前端页面（`*.tsx`、`*.vue`）的事件处理函数 | 入口找到了 |
| 后端路由（`@router.post(...)` 下面的函数） | 接口找到了 |
| 交付团队的 `SKILL.md`、`api.md`、README | 只是线索，要往后端追有没有对应实现 |
| 只有文档命中、代码零命中 | 这个功能可能没实现，或者名字不对，换词再搜 |

## 三段对上

1. 前端：按钮文案 → 事件处理函数 → 串行调用的接口列表，记下函数名和行号范围。
2. 接口：每个接口的路径和请求体字段。
3. 后端：每个接口对应的路由函数，往下追到拼 prompt 的地方。

任何一段对不上，定位就不成立。

## 找合并点

在后端函数里搜这些模式：

```bash
grep -n 'join(' <file>
grep -n 'merged_\|parts\.append' <file>
```

找到以后确认三件事：合并了多少个上游结果、每个结果有没有截断、这一次调用是不是只有一个请求。

## 找无上限维度

- 数量：上游拆出多少个，有没有 `[:N]` 或 `max_count` 封顶。
- 长度：在同一个文件里搜 `[:1500]`、`[:3000]`、`_WARN_CHARS`，看出问题的这一步有没有同样的截断。
- 粒度：切片逻辑在哪个解析器里（按章、按条、整篇），切不出来时退到什么粒度。

## 模型侧

- 内置的窗口上限和输出上限在哪（通常是模型客户端里的默认值表），能不能被配置覆盖。
- `max_tokens` 怎么算：只缩输出，还是会检查输入是否已经超窗。只缩输出的，输入一旦超过窗口就是死线，代码不会拦。

## 交付文档与代码不一致

把交付团队的 `SKILL.md`、`api.md` 和代码对照一遍。常见的不一致有两种：数量写得不一样（文档写取 2 条，代码是随机抽 3 条）；文档里有、后端没实现的接口。这些单独列出来，加进行动项。
