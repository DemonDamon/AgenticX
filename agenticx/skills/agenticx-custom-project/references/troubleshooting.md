# 出错了怎么办

每条都按「你看到什么 → 原因 → 下一步」写。下一步做完再判断项目本身，不要把环境问题当成代码缺陷。

脚本退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 这一步完成。草稿成功时，状态仍然是尚未提交。 |
| 1 | 只有 `doctor`。当前用来运行脚本的 Python 低于 3.10。后面的检查结果仍然要读。 |
| 2 | 参数不对、结论不允许提交，或 GitHub CLI 失败。以「尚未提交」为准。 |
| 3 | 发现密钥。草稿文件没有写入，也没有提交。 |

## 当前 Python 低于 3.10

你看到：`Python 版本：3.x 低于 AgenticX 要求的 3.10`，doctor 的退出码是 1。

原因：系统自带的 `python3` 常常是 3.9，不能用来安装 AgenticX。这不等于机器上没有更高版本。

下一步：

1. 若同一段输出里有「改用已经装好的更高版本」，用它打印的那个路径重新运行 `doctor` 和 `plan`。
2. `plan` 的安装命令会改成那个更高版本。照抄它，不要再执行旧解释器的 pip。
3. 没有更高版本时，安装 Python 3.10 或以上。Windows 从 python.org 安装时勾选 Add python.exe to PATH，然后关掉窗口重开。不要修改系统目录里的旧 Python。

## agx 不是命令，或 doctor 说没找到 agx

你看到：`agx 命令：没找到`，或 Windows 说「不是内部或外部命令」。

原因：还没安装，或安装后的 Scripts 目录不在当前窗口的 PATH 里。

下一步：

1. 执行 doctor 或 plan 给出的那一条 `pip install`。解释器必须是 3.10 或更高。
2. 关掉终端再开一次。
3. Windows 仍失败时，到 Python 安装目录下的 `Scripts` 看有没有 `agx.exe`，把该目录加入用户 PATH。不要把整个仓库路径加进去凑数。

若 doctor 写的是「找到了，但 20 秒内没有返回」：这是 Python 冷启动慢，不是项目创建失败。再直接运行一次 `agx --version`。

## pip 超时或连不上 pypi.org

你看到：`连接 pypi.org:443：失败`，或 pip 停在 `Connecting`。

原因：当前网络到不了 PyPI。不是 `requirements.txt` 写错。

下一步：

1. 使用你们单位已经在用的包镜像。
2. 没有现成镜像时，只执行 doctor 打印的这一次安装命令（清华镜像）。不要执行 `pip config set global.index-url`，以免改掉别人的全局配置。
3. 镜像也失败时，把 pip 的最后一行报错留下来。不要反复重试同一条命令。

## 连接 github.com 失败

你看到：`连接 github.com:443：失败。国内网络里这很常见`。

原因：只说明现在到不了 GitHub。分类、初始化和写草稿都不依赖这次连接。

下一步：

1. 继续做业务仓库里的事。
2. 需要官方结论时，草稿写「尚未对照最新上游」。
3. 不要说已经看过最新代码，不要说已经提交。
4. 稍后换网络，或把 `.agenticx-upstream` 里的草稿交给能打开 GitHub 的人。网页地址是 `https://github.com/DemonDamon/AgenticX/issues/new`。

## 参数不被接受

你看到：`参数不对：改动类型 --kind 不能是「foo」`，退出码 2。

原因：值不在可用列表里。

下一步：按报错里的「可用值」修改。中文也可以，例如 `--kind 缺陷 --where 运行时 --cause-clear 明确 --size 小`。不要发明新的类型名。

## 草稿被密钥检查拦住

你看到：`第 N 行：密钥赋值` 或「私钥」「令牌前缀」「Bearer 令牌」，退出码 3。

原因：正文里有密码或密钥后面跟着具体内容、访问令牌，或私钥开头。报错故意不打印那一行。

下一步：

1. 删掉真实的值。占位可以留空，例如单独一行 `OPENAI_API_KEY=`，这样不会被拦住。
2. 不要把密钥贴回对话。
3. 重新运行 `draft`。文件在通过之前不会写下。

## 第二次写入项目目录被拒绝

你看到：`目录里已经有文件。没有覆盖任何东西。`

原因：`--write` 发现目标目录非空。

下一步：换一个 `--name`，或者由用户自己清空那个目录后再运行。不要加参数强制覆盖，这个脚本没有覆盖开关。

## 分叉命令没有帮我执行

你看到：`本技能不会克隆仓库，也不会修改 git remote。`

原因：这是预定行为，不是失败。自动克隆会改用户的目录和 remote。

下一步：由用户自己复制打印出来的 `git clone` 命令。确认远程地址是他们自己的，再添加 `origin`。不要推到 `upstream`。

## submit 说尚未提交

你看到：以「尚未提交」开头，退出码 2。

按最后一句对号入座：

| 最后一句在说 | 下一步 |
| --- | --- |
| 当前结论不能创建 PR | 先按 classify 的结论做。还没核对上游就不要创建 PR。Issue 是否允许，看结论里的 `issue=yes`。 |
| 当前结论不能创建官方 Issue | 这次应该留在自己的仓库，不要开官方 Issue。 |
| 找不到草稿 | 先运行 `draft`。 |
| 没有找到 gh | 用浏览器把草稿贴到官方 Issue 页面。 |
| GitHub CLI 失败 | 读最后一行。常见是没登录或网络中断。不要重试推送。登录需要用户自己完成，不要在脚本里跑交互式登录。 |

加上 `--execute` 之前，先看一遍将要执行的 `gh issue create` 或 `gh pr create`。那一行里不应该出现 `git push`。

## 中文乱码

Windows 命令提示符：

```bat
set PYTHONUTF8=1
py -3 scripts\custom_project.py doctor
```

PowerShell：

```powershell
$env:PYTHONUTF8=1
py -3 scripts\custom_project.py doctor
```

macOS 和 Linux 的终端一般不需要这一步。

## 自检失败

你看到：`自检失败：` 后面有一条「期望 A，实际 B」。

原因：判断表和实现不一致，不是用户项目的 bug。

下一步：不要带着失败的自检去给用户提 PR。先修技能里的 `classify`，让 `self-test` 回到「自检通过」。自检不联网。
