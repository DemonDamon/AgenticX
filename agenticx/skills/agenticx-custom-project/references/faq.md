# 常见问题

## 我只是在用 Near 聊天，要用这个技能吗？

不用。这个技能只处理「建一个开发仓库」和「要不要把问题回报给官方」。

## 我想 5 分钟跑通第一个智能体，走哪条？

不走这个技能的分叉和 PR 流程。安装官方包后按快速上手写示例即可。等你要建客户仓库，或要决定 bug 留在哪，再回到这里。

## 客户让我改一句按钮文案，要给官方提 PR 吗？

不要。文案、颜色和客户规则留在业务仓库，也不必为此去查官方仓库。

```bash
python3 scripts/custom_project.py classify --kind style --where business
```

## 框架里有个小 bug，我已经知道改哪一行。要先搜一遍 GitHub 吗？

不要。原因清楚的小缺陷默认在当前仓库修，包括共享运行时里的小修。修完做一次针对性测试即可。不必联网，不必开 Issue。

同一批里的同类小修，以后可以合成一个 PR。不要一行开一个，也不要混进无关功能。

## 我想做一个所有用户都能用的新能力，但公司网络打不开 GitHub。

业务部分可以先做。通用部分先写草稿，草稿里保留「尚未对照最新上游」和「尚未提交」。不要写成已经确认官方没有，也不要因为 PR 还没发出去就停掉交付。

网络恢复后，只核对这次功能相关的目录和标题对得上的 Issue，再把 `--upstream-has` 改成 `yes` 或 `no` 重新判断。

## 官方已经有人修了，我还要在自己仓库再写一遍吗？

不要重写。优先升级你们锁定的版本；做不到就只移植需要的那一段和它的依赖。不要把整个官方仓库合并进来，也不要恢复你们已经决定不带的模块。移植后删掉被官方覆盖的重复补丁，并记下你实际看过的版本或提交号。

## enterprise 目录里的问题为什么不能直接提 PR？

官方贡献说明写明：员工门户、管理台和 Go 网关目前不接受事先没有约定的外部 PR，这种 PR 会被直接关闭。请先开 Issue。维护者在 Issue 里同意之后，再提 PR。

`agx project create --template enterprise` 只是应用模板的名字，和这个目录不是一件事。

## 草稿已经写好了，能不能告诉用户已经提交？

不能。草稿写在 `.agenticx-upstream/`，状态就是尚未提交。只有 `submit --execute` 成功，并且 GitHub CLI 返回了链接，才能说已经创建。失败时把脚本的最后一行原因一起告诉用户。

## 没有安装 GitHub CLI，还能反映问题吗？

能。草稿照常写。提交时用浏览器打开 `https://github.com/DemonDamon/AgenticX/issues/new`，把草稿贴进去。不要为了写草稿去安装 `gh`。

## 客户的真实单据能放进复现步骤吗？

不能。用合成数据。用户说出的客户名称、项目代号，在 `draft` 上重复加上 `--hide`。内网地址会被换成「内网地址已隐藏」。密钥赋值会直接拦住，文件不会写下。

## 各业务仓必须使用同一个 AgenticX 版本吗？

不必。每个仓库用自己验证过的版本。不要为了一次修复强制所有仓库同步，也不要声称「所有仓库都已经同步」——没验证的就标明没验证。

## 官方 PR 还没合并，我们的项目要停吗？

不要停。业务修复和交付可以先进行。上游合并之后，再在你们的集成节点升级或去掉被覆盖的本地补丁。不要开一个定时任务每天去问 PR 状态。

## 助手在他的电脑上启动了 Demo UI，我的笔记本为什么打不开 127.0.0.1:8765？

`127.0.0.1` 是**运行服务那台机器**的环回地址。服务跑在助手桌面或远程电脑上时，这个地址只在那台机器上有效，不是用户笔记本的。

下一步二选一：在运行服务那台机器（助手桌面）的浏览器里打开；或由助手截图展示。只有服务真的跑在用户本机时，才说「在你电脑上打开 localhost」。

## 想给 Demo UI 换皮，是把这个技能改一改，还是把设计技能并进来？

都不行。UI 美化、设计系统指引用**独立**的设计类技能，与本技能按兄弟技能并列组合（SkillHub 发现、确认后安装）。**不要**把第三方设计技能的正文合并进 `agenticx-custom-project`。换皮本身判业务 style：

```bash
python3 scripts/custom_project.py classify --kind style --where business
```

结论是留在业务仓，不提上游 PR。

## Windows 提示 agx 不是内部或外部命令，是不是安装坏了？

多半是新开的窗口还没拿到 PATH，或 Python 的 Scripts 目录不在 PATH 里。关掉「命令提示符」或 PowerShell 再开一次。仍没有时，用 doctor 打印的那条 `py -3 -m pip install agenticx`，不要猜一个安装路径。

中文变成乱码时，命令提示符先执行 `set PYTHONUTF8=1`。

## pip 一直转圈或报连不上 pypi.org，是依赖写错了吗？

不是。这是网络。doctor 会写明 `pypi.org:443` 失败。优先用你们单位已经在用的镜像。没有镜像时，只用 doctor 给出的那一条清华镜像命令，它只影响这一次安装，不要写进全局 pip 配置。

## 脚本说第 N 行是密钥，可我没看见密钥？

它故意不把那一行的内容打印出来。请到草稿来源里看那一行，是不是密码、密钥或令牌后面写了具体内容。删掉具体内容再运行。只有空着的环境变量名字时，不会被当成密钥。

## 判断结果和我的直觉不一样，能改吗？

不能改脚本已经给出的结论。若事实没说全，把缺的事实补成参数再跑一次。例如你后来确认官方已经有了，就加上 `--upstream-has yes`，结论会从「先核对」变成「移植」。

## 分叉和精简拷贝有什么不同？

分叉是完整克隆官方仓库，用 git 跟上游。精简拷贝只拿走需要的目录，并在 `UPSTREAM_NOTES.md` 写清版本、裁了什么、本地补丁是什么。两种都不要自动执行。客户业务都不要放进去。

## 仓库里已经有一段 agenticx-upstream-policy，以谁为准？

以仓库里 `<!-- agenticx-upstream-policy:start` 到 `end` 的原文为准，不要改写。本技能的 [upstream-policy.md](upstream-policy.md) 是同一套约定的操作说明，供还没有这段标记的新仓库使用。
