绘制一张标题为“AgenticX Enterprise 架构”的企业级横向分层架构图，核心表达：

4. 企业数据基础设施

主聊天链路从左向右；控制关系从上向下；演进关系使用虚线。主链路不得交叉，目标能力不得接入当前默认粗实线链路。

[视觉模块详解]

一、顶部“企业访问层｜已落地”

使用深蓝紫横向容器（细铬银描边），内部放置三类角色与入口：

1. 人物图标“企业员工”
   → “Web Portal”

2. 人物图标“平台管理员”
   → “Admin Console”

3. 应用图标“企业应用 / API 客户端”
   → “Go AI Gateway”

企业员工不得直接连接 Go AI Gateway，必须先进入 Web Portal。

二、左上“企业控制面｜已落地”

使用深底、电光蓝实线描边（细金属高光）的大容器。

顶部放置核心节点：

“Admin Console”

下方采用两行三列排列六张治理能力卡片：

- “身份与权限”
- “模型与通道”
- “策略规则”
- “Token 与配额”
- “审计查询”
- “合规与运维”

“会话与历史”不得放在 Admin Console 内；它属于 Web Portal 工作区与业务数据。

从控制面向数据库绘制细实线双向箭头，标注“治理配置读写”。

从“模型与通道”“策略规则”“Token 与配额”汇聚成一条细实线，指向 Go AI Gateway，标注“配置快照 / 热加载”。

明确控制面负责治理与配置，不承载模型推理或完整 Agent 执行。

三、中央左侧“Web Portal 与 Portal BFF｜已落地”

使用深底电光蓝实线容器，内部从左到右放置：

- “聊天工作区”
- “会话与历史”
- “可见模型校验”
- “Portal BFF”

从“企业员工”到“聊天工作区”绘制粗实线。

从“聊天工作区”到“Portal BFF”绘制粗实线，标注“POST /api/chat/completions”。

从 Portal BFF 到数据库绘制细实线双向连接，标注“会话归属 / 消息持久化”。

从 Portal BFF 到 Go AI Gateway 绘制粗实线，标注“JWT + Provider Context”。

四、中央“Go AI Gateway｜在线主链路 · 已落地”

使用面积最大的深蓝紫核心容器（边缘可有极弱电光蓝 / 紫罗兰 bloom），将“Go AI Gateway”作为核心。

内部从左向右排列六个连续处理节点：

1. “鉴权与主体”
   副标题：“JWT / PAT · Tenant / Dept / User”

2. “配额与限流”
   副标题：“TPM / RPM · Budget”

3. “缓存与请求策略”
   副标题：“精确 / 语义缓存 · Policy”

4. “模型与通道路由”
   副标题：“Channel · KeyPool · Relay”

5. “响应策略”
   副标题：“流式检查 · 脱敏”

6. “审计与用量”
   副标题：“Audit Chain · Token Usage”

六个节点由一条连续电光蓝粗实线贯穿（可带极弱蓝紫光晕）。

在 Gateway 容器底部增加一条无外框能力带：

- “跨境合规”
- “Wasm Hooks”
- “MCP Host / Proxy”
- “故障转移”

能力带不再增加内部箭头，避免信息过载。

从企业 API 客户端到 Gateway 绘制另一条粗实线，标注“JWT / PAT 直连”。

Gateway 通过反向粗实线返回 Portal BFF 和 API 客户端，标注“普通 / 流式响应”。

在容器下方以醒目但克制的文字标注：

“当前职责：企业合规网关与模型请求中继，不等同于完整 Agent Runtime”

五、右中“上游兼容模型服务｜外部能力”

放在“企业私有化部署域”之外，使用简洁云形轮廓。

内部放置：

- “OpenAI 兼容接口”
- “企业专属模型服务”
- “其他兼容提供方”

从 Gateway 的“模型与通道路由”绘制粗实线指向外部模型，标注“模型请求”。

返回箭头标注“普通 / 流式响应”。

不得加入未经确认的具体模型厂商名称或 Logo。

六、底部“企业数据基础设施｜已落地”

使用深蓝灰横向容器，内部放置：

1. 标准圆柱形“PostgreSQL（默认）/ MySQL（可选）”
   - 身份与权限
   - 会话与历史
   - 运行时配置
   - Token 用量
   - 策略与审计索引

2. 标准圆柱形“Redis｜可选”
   - 精确 / 语义缓存
   - 分布式 TPM / RPM 限流
   - 未配置时可内存降级

3. 文件形“追加式审计日志”
   - JSONL 哈希链
   - 必须成功的本地兜底

从 Portal BFF 到数据库绘制细实线双向箭头，标注“会话与消息”。

从 Admin Console 到数据库绘制细实线双向箭头，标注“治理配置”。

从 Gateway 到数据库绘制细实线，标注“用量与审计索引”。

从 Gateway 到 Redis 绘制细实线双向箭头，标注“缓存 / 限流”。

从 Gateway 到审计日志绘制细实线，标注“追加式审计兜底”。

不得将临时聊天会话状态标为 Redis 的主要职责。

七、右侧“Agent Runtime 演进区”

使用独立暗紫灰虚线大容器，与当前在线主链路保持明显间距。

内部上下排列：

1. “Enterprise Edge Agent｜MVP”
   - Go Sidecar
   - 任务沙箱与 Trace
   - 经 Gateway 调用模型
   - 状态：“已存在 · 未进默认链路”

该节点使用深底暗紫灰虚线框。不得与 Near Desktop 的 Python `agx-server` 混称或合并。

2. “Cluster Agent Runtime｜未来”
   - K8s / 多副本
   - 统一调度与高可用
   - 状态：“未开始”

该节点使用低视觉权重的暗紫灰虚线框。

从 Gateway 向 Edge Agent 绘制细虚线双向连接，标注“可选任务路由 / 模型中继”。

从控制面向 Cluster Runtime 绘制细虚线，标注“未来治理与调度”。

不得从 Web Portal 直接以粗实线连接 Edge Agent 或 Cluster Runtime。
