## 文档说明

### 文档目的

本文档明确智能投标解析与AI辅助评标系统的功能边界、业务规则、技术指标、接口规范与验收标准，用于指导系统开发、项目实施与最终验收，支撑公司采购评审环节数字化升级，实现评审效率提升、标准统一与合规风险可控。

### 适用范围

本系统适用于公司全品类采购项目的招标评审场景，覆盖比选、框架短名单入围、询价、竞争性谈判、单一来源等多种采购方式，供采购管理部门、评审专家、合规审计部门使用。

### 术语定义

| 术语 | 定义 |
|------|------|
| 重大偏离 | 投标文件未满足招标文件中标注★的实质性要求，直接影响投标有效性的偏离情形 |
| 一般偏离 | 投标文件未满足非实质性要求，不影响投标有效性的偏离情形 |
| 无效投标 | 因资质不符、关键文件缺失、签章无效等原因，不具备评审资格的投标 |
| OCR | 光学字符识别，用于将扫描件、图片格式的投标文件转换为可编辑文本 |
| NLP | 自然语言处理，用于投标文件语义理解、信息提取与一致性比对 |

## 一、项目概述

### 1.1 项目背景

随着公司业务规模扩大与跨境采购品类拓展，评审环节工作量持续增长，传统人工评审模式存在以下突出问题：

1. 投标文件多以大页数PDF、扫描件形式提交，人工摘录信息、核对参数耗时久，大型项目评审周期长，效率难以匹配业务推进节奏；
2. 评审标准依赖评委个人经验理解，不同评委打分尺度存在差异，评审结果一致性不足；
3. 围串标、资质造假等隐蔽风险，依赖人工经验识别难度大，合规管控存在隐患；
4. 跨境采购项目涉及多语言投标文件、海外供应商资质核验，进一步提升了评审复杂度与人工成本。

为落实公司采购数字化转型要求，规范评审全流程、强化合规管控、提升评审效率，拟建设智能投标解析与AI辅助评标系统，通过OCR识别、自然语言处理、智能算法等技术，替代人工完成投标文件解析、信息核对、风险初筛等事务性工作，辅助评委开展专业评审。

### 1.2 建设目标

#### 1.2.1 业务目标

1. 提升评审环节工作效率，项目信息解析与核对周期由数天降为小时级；
2. 法定无效投标情形识别全覆盖，降低人工漏判风险；
3. 统一评审标尺，提升评审过程与结果的公正性；
4. 强化采购风险识别能力，提升围串标、资质不符等风险的发现率；
5. 评审全流程操作留痕、数据可追溯，满足内部审计与合规管控要求。

#### 1.2.2 技术目标

1. 支持多格式、多渠道投标文件统一接入与自动化解析，兼容中英文双语标书；
2. 基于采购领域语料优化模型能力，实现招投标专业术语、评审规则的精准识别；
3. 提供可视化规则配置能力，业务人员可自主调整评审规则与评分标准，无需代码开发；
4. 采用模块化、可扩展架构，可与公司现有采购系统集成。

### 1.3 建设原则

1. 业务驱动：贴合采购评审实际业务流程，不改变评审核心权责，系统定位为辅助工具，最终决策由评委确认；
2. 合规优先：所有功能设计符合国家招投标相关法律法规与公司采购管理制度，满足合规审计要求；
3. 准确可靠：核心信息提取与规则判定保持高准确率，异常结果自动标记人工复核，避免误判；
4. 灵活扩展：评审规则、评分标准、风险阈值支持自定义配置，适配不同品类、不同规模的采购项目。

## 二、系统总体架构

### 2.1 整体架构设计

系统采用四层架构设计，实现数据与业务解耦，保障扩展性与稳定性：

1. 数据接入层：支持本地批量上传、采购系统同步两种接入渠道，兼容PDF、Word、Excel、图片、压缩包、加密签章文件等多格式文件，完成文件校验、格式转换与预处理。
2. AI引擎层：包含OCR识别引擎、NLP语义解析引擎、规则推理引擎、风险分析引擎四大核心引擎，负责文本识别、信息提取、规则比对与风险计算。
3. 业务应用层：包含投标文件解析、无效投标筛查、智能评分、偏离比对、评标辅助、风险预警六大核心功能模块。
4. 交互展示层：提供PC端Web操作界面，支持解析结果可视化、偏离项定位、在线评审、报告导出等交互能力，适配采购经办人、评审专家、采购负责人、合规审计四类角色。
5. 支撑体系：覆盖权限管理、日志审计、规则配置、数据安全四大基础支撑能力。

### 2.2 核心技术路线

1. OCR识别：高精度版面分析OCR，支持复杂表格、公章、手写签名、多语言文档识别；
2. NLP引擎：基于采购领域语料优化的语言模型，支持专业术语理解、长文档语义比对、信息结构化提取；
3. 规则引擎：可视化规则配置引擎，支持零代码配置废标规则、评分规则、偏离判定规则；
4. 风险算法：文本相似度算法、关联关系图谱算法，用于围串标与异常风险识别。

### 2.3 核心业务流程

1. 采购经办人上传采购需求文件与评分标准，系统完成评审规则结构化配置；
2. 多渠道归集所有供应商投标文件，批量完成AI解析与信息结构化提取；
3. 系统自动执行无效投标筛查、风险识别、客观项初评分；
4. 自动比对投标文件与采购需求，生成偏离项清单并分级标注；
5. 评委在线查看解析结果、偏离报告与事实性参考信息，独立完成项目打分；
6. 系统自动汇总评审结果，生成正式评标报告与风险分析报告，同步归档。

## 三、核心功能需求

### 3.1 投标文件智能解析模块

#### 3.1.1 多渠道文件接入与预处理

功能描述：实现全渠道投标文件的统一归集、自动化预处理与供应商自动匹配，减少人工整理工作量。

功能要求：

1. 多格式文件支持
   - 支持可编辑PDF、Word、Excel、PPT格式电子投标文件；
   - 支持扫描件PDF、JPG、PNG等图片格式投标文件；
   - 支持带CA签章的加密PDF、工程量清单文件解析；
   - 支持ZIP、RAR格式压缩包，自动解压并按文件夹、文件名自动关联对应供应商；
   - 单文件支持2GB（如遇超大文件，需有后台临时处理方式），兼容2000页以内的工程类、服务类大页数标书；单次批量上传支持不少于500份文件。
2. 文件预处理
   - 自动完成扫描件去噪、旋转矫正、清晰度增强，提升识别准确率；
   - 自动校验文件完整性，识别损坏、加密、无法读取的文件并标记异常；
   - 自动生成文件唯一标识与版本号，全程追溯文件来源与修改记录。

#### 3.1.2 投标信息结构化解析

功能描述：通过OCR与NLP技术，对投标文件进行深度语义解析，自动提取全维度关键信息并结构化存储，替代人工摘录。

功能要求：

1. 供应商资质信息提取与核验
   - 自动提取供应商全称、统一社会信用代码、注册地址、法定代表人、联系方式等基础工商信息；
   - 自动识别各类资质证书（营业执照、行业资质、ISO认证、专业许可证等），提取证书名称、等级、有效期、发证机关；
   - 对接官方资质查询数据源，对核心资质证书进行联网验真，自动识别过期、吊销、等级不符的无效资质；
   - 自动提取供应商过往业绩，提取项目名称、甲方单位、合同金额、项目时间，形成业绩清单，并支持交叉校验。
2. 技术与商务响应信息提取
   - 自动提取技术方案核心内容，按采购需求的参数条目逐一匹配响应内容；
   - 自动提取商务履约条款：交付周期、交货地点、付款方式、质保期限、验收标准；
   - 自动提取售后服务方案：服务团队配置、响应时效、维保范围、培训方案、应急保障机制；
   - 支持中英文双语标书自动解析，非中文内容自动翻译后同步提取结构化信息。
3. 签章有效性识别
   - 自动识别投标文件的公章、法人章、授权代表签字，定位签章位置；
   - 校验关键页（投标函、报价表、授权书）是否按要求签章，缺失则自动标记；
   - 支持电子签章验真，识别伪造、过期的电子签章。
4. 低置信度内容标记
   - 对识别置信度低于80%的信息自动标记为「待人工复核」，标注原文对应位置；
   - 支持人工修正解析结果，修正结果自动纳入模型优化样本库。

#### 3.1.3 无效投标自动筛查

功能描述：内置法定无效投标规则库，支持自定义项目废标规则，自动筛查无效投标并生成判定依据。

功能要求：

1. 无效投标规则库
   - 内置法定无效情形：供应商不具备独立法人资格、资质证书过期/等级不达标、无有效签章等；
   - 支持自定义项目规则：缺失★号关键文件、交付周期不满足实质性要求等；
   - 规则支持配置"一票否决""警告提示"两种处置等级。
2. 自动判定与证据生成
   - 解析完成后自动执行全量规则校验，逐家供应商输出无效判定结果；
   - 支持语义级判定，识别供应商通过文字表述规避实质性要求的隐蔽无效情形；
   - 对判定为无效的投标，明确标注无效原因、对应规则条款、文件佐证位置，自动截取原文片段形成完整证据链；
   - 支持按无效原因、供应商名称筛选查看，批量导出无效投标清单。
3. 人工复核机制
   - 系统判定结果为初步建议，支持采购人员/评委人工复核；
   - 复核可执行「确认无效」「恢复有效」操作，操作全程留痕，记录复核人、复核时间、复核意见；
   - 复核通过的有效投标自动进入后续评审环节。

#### 3.1.4 客观项自动量化评分

功能描述：按照预设的评分规则，对投标文件中的可量化客观指标自动计算得分，减少人工计算误差；主观评分项保留人工打分入口，系统不做自动赋值与打分引导。

功能要求：

1. 评分规则配置
   - 支持拆分客观评分项与主观评分项，分别配置规则与分值；
   - 客观评分项（资质分、业绩分、商务分等）支持配置计算规则，资质分、业绩分支持按证书等级、业绩数量/金额自动匹配对应分值；
   - 主观评分项仅配置项名称、分值上限、评审要点（由采购经办人手动录入评审参考维度），系统不预设打分标准、不提供建议分值。
2. 自动计算与追溯
   - 基于解析提取的结构化信息，自动计算所有客观项得分，生成分值明细；
   - 自动汇总单家供应商客观分总分，标记得分计算依据与对应文件位置；
   - 评分计算过程可追溯，支持点击分值查看计算公式与原始数据。
3. 主观分录入入口
   - 技术方案、服务质量等主观评分项，预留人工打分输入框，由评委自主填写分值；
   - 系统仅校验分值是否在设定的分值区间内，防止超分、漏分等操作失误，不干预评委打分尺度。

#### 3.1.5 采购风险智能识别

功能描述：通过多维度算法模型，识别围串标等采购风险，分级预警并提供佐证依据。

功能要求：

1. 围串标风险识别
   - 文档属性维度：解析文件底层元数据，识别不同供应商投标文件的作者、编辑设备、创建时间、宏代码、修改痕迹等同源特征；
   - 文本特征维度：计算技术方案、商务表述的文本相似度，同时识别句式、错别字、段落结构等隐性特征雷同；
   - 主体关联维度：识别供应商之间股权交叉、高管重叠、实际控制人关联等情形，穿透不少于三层关联关系。
2. 风险分级与处置
   - 风险分为高、中、低三个等级，高风险自动推送至采购负责人与合规岗；
   - 每条风险附带完整证据链，包含风险描述、对比数据、原文位置；
   - 支持人工标注风险核实结果，核实记录自动归档。

#### 3.1.6 解析结果展示与报告生成

功能要求：

1. 多维度结果展示
   - 项目总览：展示投标供应商总数、有效/无效投标数量、风险预警数量等核心指标；
   - 供应商横向对比：对比所有供应商的资质、报价、业绩、质保期等核心指标，支持自定义对比维度；
   - 原文穿透：点击任意结构化字段可跳转至投标文件原文对应位置，快速核验信息。
2. 解析报告生成
   - 自动生成投标文件解析与评审辅助报告，包含项目概况、投标单位清单、无效投标说明、核心信息对比表、风险预警清单、客观得分初评表；
   - 报告支持导出Word、PDF格式，可直接作为评审档案归档。

### 3.2 AI辅助评标模块

#### 3.2.1 评审规则结构化管理

功能描述：将招标文件中的采购需求、技术参数、评分标准转化为结构化评审项，作为AI比对与评审的基准。

功能要求：

1. 采购需求自动解析
   - 支持上传招标文件、采购需求说明书，自动提取技术参数清单、商务要求清单；
   - 自动识别并标注实质性条款（★号项）与一般条款，区分参数重要等级；
   - 支持人工编辑、新增、删除评审项，调整参数权重与重要性等级。
2. 评分规则配置
   - 支持综合评分法、最低价中标法等多种评审办法；
   - 支持拆分评分项，设置每项分值、评分标准、打分依据、偏离扣分规则；
   - 规则版本化管理，修改自动留存历史版本，可追溯可回滚。

#### 3.2.2 投标需求一致性比对

功能描述：自动比对投标响应内容与采购需求，精准定位所有偏离项并分级标注，替代人工逐页核对。

功能要求：

1. 全维度偏离识别
   - 技术参数偏离：逐一比对每项技术参数，识别正偏离、负偏离、无偏离；
   - 商务条款偏离：比对交付周期、质保期、付款方式、验收标准等商务要求；
   - 资格条件偏离：比对供应商资格、资质、业绩等准入条件的满足情况；
   - 自动识别投标文件前后表述矛盾、承诺不一致的内部偏离项。
2. 偏离分级与定位
   - 自动判定偏离类型：实质性条款不满足判定为「重大偏离」，一般条款不满足判定为「一般偏离」；
   - 每条偏离项清晰展示：需求原文、投标响应原文、偏离类型、所在页码与段落位置；
   - 支持按偏离类型、参数类别、供应商筛选查看，一键导出偏离项汇总表。
3. 偏离统计与联动
   - 自动统计每家供应商的重大偏离数量、一般偏离数量，计算偏离率；
   - 支持横向对比所有供应商的偏离情况，按偏离数量排序；
   - 偏离项自动关联评分规则，根据偏离等级自动计算对应扣分值；重大偏离供应商自动触发废标提示。

#### 3.2.3 评审辅助支撑

功能描述：基于全量解析数据与偏离结果，为评委提供事实性信息汇总与检索支撑，不干预评委主观判断，最终评审结论与打分由评委独立完成。

功能要求：

1. 供应商信息全景呈现
   - 针对每家供应商整合展示全量事实信息，包括资质情况、业绩清单、报价明细、偏离项清单、风险预警项；
   - 以雷达图形式直观呈现供应商在资质、业绩、技术响应、报价、服务、风险六个维度的事实性指标对比，不做优劣定性评价。
2. 评审要点提示
   - 基于采购文件预设的评审要点，在评委打分页面同步展示对应评审维度说明，仅作流程提示；
   - 对存在重大偏离的供应商，系统自动标注并提示对应规则条款，不直接给出废标或打分建议，最终判定由评委确认。
3. 智能问答助手
   - 支持评委以自然语言提问，系统基于项目全量投标数据与采购文件自动作答；
   - 答案仅返回事实性信息与原文出处，不输出倾向性评审意见。

#### 3.2.4 在线评审协同

功能描述：提供在线评审工作台，支撑多评委同步独立评审，规范打分流程，监控评审进度，保障评审过程独立、可追溯。

功能要求：

1. 评委工作台
   - 按评委角色分配评审权限，仅可查看权限范围内的投标文件与评分项；
   - 工作台集成解析结果、偏离报告、原文查看、打分入口，无需切换页面。
2. 打分合规校验
   - 校验打分完整性：未完成所有评分项无法提交评审结果，防止漏项；
   - 校验分值合法性：主观打分超出该项分值上下限时，自动弹出操作提示，要求确认修正，仅防止误操作，不限制评委正常打分尺度；
   - 支持评委提交个人评审意见，系统自动归集汇总。
3. 进度监控
   - 采购负责人可实时查看所有评委的评审进度、已完成打分项、剩余工作量；
   - 支持发送评审提醒至对应评委。

#### 3.2.5 评审结果汇总与公正性校验

功能要求：

1. 结果自动汇总
   - 自动汇总所有评委的打分结果，按权重计算最终得分，生成供应商排名；
   - 自动生成评分明细表，展示每位评委对每家供应商的各项打分；
   - 支持按得分、偏离数量等多维度排序查看。
2. 评分离散度分析
   - 计算每位评委打分的离散度，打分偏离全体平均分超过设定阈值自动标记为异常打分；
   - 识别倾向性打分特征，如某评委对特定供应商打分显著偏离整体水平，自动标注供评审组长复核；
   - 生成分数离散度分析表，仅作为评审复核与审计参考，不自动修正评委打分结果。
3. 复核机制
   - 支持评审组长对异常打分进行复核，可要求评委说明理由或自行修正；
   - 复核操作全程留痕，修改记录与理由自动归档。

#### 3.2.6 评标报告自动生成

功能要求：

1. 自动生成正式评标报告，包含项目概况、评审委员会组成、评审过程说明、无效投标说明、偏离情况汇总、评分结果与排名、推荐中标候选人、风险提示与建议；
2. 支持自定义报告模板，适配不同采购类型的报告格式要求；
3. 支持导出Word、PDF格式，支持批量打印；
4. 报告与所有原始文件、解析数据、操作日志自动归档，关联对应采购项目，支持检索与审计。

## 五、数据安全与合规要求

### 5.1 数据安全防护

### 5.3 审计与留痕

### 7.2 验收标准与付款

本项目验收考核分为三个阶段，包括初验考核、终验考核及系统运维保障服务考核。考核采取扣分制，考核得分将作为付款结算依据。各阶段验收考核要求如下：

初验考核为版本发布期的质量考核，考核时间在对应功能交付上线后进行，具体考核细则详见附录-表1《初验考核表》。初验以完成全部功能并通过需求方验收为准，如验收未通过，卖方需按原定需求说明进行逐一整改，并在指定时间内完成复验，复验时任一功能仍未通过，则以不合格结果处理。

终验考核为系统试运行期的质量考核，考核时间在版本上线后的三个月内进行，主要考核系统上线后的运行质量和面向真实客户人群的使用质量，具体考核细则详见附录-表2《终验考核表》。

系统运维保障服务考核为产品推广期的质量考核，考核时间在需求方终验考核通过之日起的6个月，主要考核系统的可靠性和稳定性，具体考核详见附录-表3《系统运维保障服务考核表》。此阶段卖方需为系统免费提供维保服务及必要的升级迭代开发服务。

需求方按"2/3/3/2"的付款条件向卖方支付款项，即项目合同签约、人员到位、卖方提供的产品需求方案经需求方审核通过，且开具发票后支付20%预付款；项目全部功能交付，且通过初验考核后支付30%；终验考核通过后支付30%；终验通过6个月后，且通过系统运营保障服务考核后支付20%。

当期实际结算金额=结算系数×当期应付金额。考核得分采取百分制，得分应大于等于0分，小于等于100分。当期考核结束后，当前得分为本阶段的最终结算依据，对应失分项的扣除费用后续也无法支付。

|------|------|
| 重大 | 导致程序无法继续运行、丧失主要功能、系统不稳定、不安全、破坏数据、或产生错误结果。主要包括：1、需求说明书中的主要功能未实现；2、造成系统崩溃、死机；3、常规操作造成程序非法退出、死循环、通讯中断或异常，数据破坏丢失或数据库异常；4、利用客户端某些操作造成服务端不能继续正常工作；5、重要数据丢失且很难恢复；6、造成人员、装备、环境等重大损失；7、错误影响到其它功能正常实现 |
| 严重 | 程序运行基本正常，但存在需求、设计或实现上的缺陷造成次要功能运行不正常，并对主要功能、性能有较大影响或造成严重损失。主要包括：1、主要功能基本能实现，但系统不稳定、一些边界条件下操作会导致超时、文件操作异常、通讯异常、数据丢失或破坏等错误；2、因错误操作迫使程序中断；3、系统性能或响应时间会变慢（响应时间为发布时的130%及以上）；4、硬件或通讯异常发生恢复后，系统不能自动正常继续工作；5、系统兼容性差，与其它程序一起工作时发生错误，而没有充分理由说明是由其他程序引起的 |
| 一般 | 程序能正常运行，但在界面显示及操作上存在问题，对软件功能性能有较小影响或造成一般损失。主要包括：1、界面不符合既定需求，辅助说明描述不清楚；2、文字描述存在错别字；3、长操作（3秒以上操作）未给用户提示（或长操作结束后提示没有消失）；4、删除操作未给出提示；5、前台有进行输入操作的控制 |

**表5：服务支撑问题分级：**

| 分级 | 定义说明 | 服务承诺 |
|------|----------|----------|
| P1 | 一级故障：系统或全部业务出现中断，无法开展日常业务 | 30分钟内响应，2小时内恢复业务，1天内提供故障分析报告，3天内提供解决方案（如需要）。因第三方软硬件问题造成的故障，不在承诺范围 |
| P2 | 二级故障：因系统原因导致部分业务无法开展 | 30分钟内响应，4小时内恢复业务，1天内提供故障分析报告，7天内提供解决方案（如需要）。因第三方软硬件问题造成的故障，不在承诺范围 |
| P3 | 用户投诉：收到用户对系统质量、服务人员或不影响业务流程流转的系统BUG等投诉事项 | 8小时内响应并回复问题查证结果，不超过24小时制定解决方案和计划，最晚5个工作日内处理完成，或提供经需求方管理人员认可的解决计划 |
| P4 | 日常运营维护：系统日常监控、BUG修复、软件版本升级、业务数据配置等 | 1、日常监控：持续监控运行指标，每周提供运行监控报告；2、BUG修复：确认为程序错误的，原则上5个工作日内完成修复或提供认可的解决计划；3、版本升级：上线前后须提供测试报告；4、业务数据配置：原则上3个工作日内完成或提供认可的时间计划；5、其他：按要求时限提供日常业务支撑服务 |
