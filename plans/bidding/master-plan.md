## 1. 总体判断

需求说明书（「智能投标解析与AI辅助评标系统」项目，甲方背景信息已脱敏）的 12 个核心需求点，本质上是一个**垂直业务域**叠在 AgenticX 已有的「解析 / 检索 / 编排 / 审批 / 评测 / 企业控制面」底座上：

- **底座直接复用约占 35% 价值**：MinerU 解析、RAG/brain 检索、flow/longrun 编排、action_proposals 审批原语、副作用账本、evaluation 评测框架、Enterprise 三栈（Portal + Admin + Go Gateway）与 IAM/RBAC/审计/计量/Trace/私有化部署。
- **业务层 100% 新建**：仓库内（`agenticx/` 与 `enterprise/`）经检索确认**不存在任何投标/评标领域代码**（aiaudit 仅提供设计参考，代码不在本仓库）。无效投标规则引擎、客观分计算、偏离比对、围串标识别、评委工作台、报告生成，全部为增量开发。
- **一期交付 Enterprise Web**（PC 端、50 并发），不含 Desktop 与 mobile。

## 3. 目标架构

在 AgenticX 三栈之上新增 `bidding` 业务域，保持与底座解耦（考核表对「产品可扩展性」单项占 10 分，业务包与底座分离是硬要求）：

```
┌─────────────────────────────────────────────────────────────────┐
│  交互层  enterprise/apps/web-portal + admin-console              │
│          挂载 enterprise/features/bidding/（新）                  │
│          页面：项目总览 / 文件归集 / 解析结果 / 偏离报告 /        │
│          评委工作台 / 风险预警 / 规则配置 / 审计检索              │
├─────────────────────────────────────────────────────────────────┤
│  网关层  enterprise/apps/gateway（Go，复用）                      │
│          IAM/RBAC 鉴权 · 审计 · 策略 · 计量 · BFF 路由（扩展）    │
├─────────────────────────────────────────────────────────────────┤
│  业务层  agenticx/bidding/（新 Python 包，FastAPI 挂 agenticx/server）│
│          intake 文件接入流水线 · extraction 结构化抽取            │
│          rules 规则引擎(无效/评分/偏离) · risk 围串标三维度        │
│          review 评审协同域(工作台/汇总) · reports 报告引擎        │
│          数据模型：项目/供应商/标书/字段/规则/评分/偏离/风险/审计  │
├─────────────────────────────────────────────────────────────────┤
│  底座层  agenticx core（复用）                                    │
│          tools/mineru · retrieval/brain · flow/longrun            │
│          runtime/action_proposals · reliability/call_ledger      │
│          evaluation · llms · safety/policy · observability       │
└─────────────────────────────────────────────────────────────────┘
```

关键架构决策：

1. **业务代码物理位置**：Python 侧新建 `agenticx/bidding/`（业务域包，不侵入底座模块）；前端新建 `enterprise/features/bidding/`（feature package 官方定制路径，参照 `features/iam` 的 api/services/components 结构）。
2. **人工复核统一走 action_proposals**：低置信度修正（SP-B2）、无效投标复核（SP-B3）、异常打分复核（SP-B6）三个场景复用同一审批原语，操作天然进企业审计链，满足需求书 5.3 全程留痕。
3. **外部写全部过副作用账本**：采购系统同步（SP-B8）、资质验真查询（SP-B2）、工商数据查询（SP-B4）均为外部副作用，走 `reliability/call_ledger` 保证崩溃后不重复调用、可对账。
4. **所有 LLM 环节必须挂评测集**：抽取、无效判定、偏离比对、围串标文本相似度的准确率指标（98%/100%/96%/90%）是验收红线，开发期即建 evalset（复用 `agenticx/evaluation/`），不允许裸调提示词。
5. **规则与代码分离**：无效规则、评分规则、偏离规则全部数据化（DB 存储 + 版本化 + 可视化配置页），业务人员可调，满足 1.2.1「无需代码开发」目标与可扩展性考核。

## 7. 横切关注点

### 7.1 评测集战略（准确率指标的生命线）
验收红线指标：印刷体 OCR≥99.8%、核心字段≥98%、法定无效 100%、偏离召回≥96%、围串标准确率≥90%/误报≤5%。策略：
- 评测集在 W1-2 与甲方共同确认并**封版签字**（合同前置条件，见评估表风险清单）；
- 每个算法环节建独立 evalset（B2 抽取 / B3 无效 / B5 偏离 / B4 相似度），复用 `agenticx/evaluation/evalset.py + llm_judge.py + runner.py`；
- CI 中跑回归，调优轮次合同限定 3 轮。

### 7.2 安全合规（对应需求书第五章 + 终验信息安全 10 项）
- 复用：Gateway 鉴权、audit 审计、policy 内容合规、会话私有目录、出站域名允许列表；
- 扩展：加密存储、敏感字段脱敏、字段级权限、日志 10 年归档（存储由甲方提供）；
- 开源合规：交付前出 SBOM 清单与 License 审查（MinerU 等确认商用合规），对齐供应链安全评估模板三项技术侧交付物。

### 7.3 知识产权（高风险项）
需求书 5.4 约定全部成果归甲方。交付口径：**AgenticX 底座为乙方既有知识产权，授予甲方永久不可撤销的内部使用许可；`agenticx/bidding/` 与 `enterprise/features/bidding/` 业务定制代码著作权归甲方**。合同列明底座/通用组件清单。交付前从 main 切 release 分支锁定 `54f0866ed`。

### 7.4 性能指标前提
100 页可编辑 PDF≤5min / 扫描件≤10min / 500 份批量≤30min / 50 并发 / 页面≤1s / 报表≤3s。批量指标按约定 MinerU 并发与 GPU 算力测算，测试前提（文件类型/算力/网络）写入验收口径；99.95% 可用性区分应用层与基础设施层。
