> 需求映射：需求书 3.2.4 在线评审协同、3.2.5 评审结果汇总与公正性校验（12 需求点 #10、#11）

## 1. 目标

多评委同步独立评审的在线工作台（权限隔离、打分合规校验、进度监控）；评审结果加权汇总、排名、离散度与倾向性分析、组长复核闭环。

## 3. 增量设计

### 3.1 评审域模型（`agenticx/bidding/review/models.py`）

```python
class ReviewAssignment(BaseModel):    # 评委回合分配
    project_id: str; reviewer_id: str
    scope: ReviewerScope             # 可见投标文件与评分项范围（权限隔离）
    status: Literal["pending", "in_progress", "submitted"]

class ReviewScore(BaseModel):         # 单项打分
    assignment_id: str; supplier_id: str; item_id: str
    score: float | None; comment: str | None
    submitted_at: datetime; revision: int

class ReviewResult(BaseModel):        # 汇总
    supplier_id: str; total: float; rank: int
    breakdown: list[ScoreDetail]      # 每评委×每项
```

### 3.2 评委工作台（前端为主）

- 集成单页：解析结果、偏离报告、原文查看、打分入口，无需切换页面
- 按评委角色分配评审权限，仅可查看权限范围内文件与评分项（数据权限与功能权限分离，联动 SP-B8 IAM 扩展）
- 主观分录入：输入框 + 分值区间校验（超分/漏分弹窗确认，仅防误操作不干预尺度）
- 评审要点提示：打分页同步展示采购文件预设的评审维度说明（仅流程提示）；重大偏离供应商自动标注 + 规则条款提示，不直接给废标或打分建议

### 3.3 打分合规校验（`agenticx/bidding/review/validation.py`）

- 完整性：未完成所有评分项无法提交（服务端强校验，非仅前端）
- 合法性：主观分超出该项上下限 → 强制确认修正
- 提交后锁定：评委个人评审意见提交后进入归集，不可静默修改（修改走组长复核链路留痕）

### 3.4 进度监控与汇总（`agenticx/bidding/review/aggregation.py`）

- 采购负责人实时查看各评委进度（已完成项/剩余量）、发送评审提醒
- 加权汇总：按评分办法权重计算最终得分、供应商排名；评分明细表（评委×供应商×各项）
- **离散度分析**：每评委打分离散度计算；偏离全体平均分超阈值自动标记异常打分；倾向性特征识别（某评委对特定供应商显著偏离整体水平）→ 标注供组长复核
- 复核机制：组长要求评委说明理由或修正；复核操作、修改记录与理由自动归档
- 红线：离散度分析仅作复核与审计参考，**不自动修正**评委打分

## 5. 验收标准

- 多评委并发独立评审（50 并发场景覆盖），权限隔离无越权（用例含横向越权攻击样本）
- 未完成所有评分项无法提交；超分强制确认
- 进度实时可视、提醒可达
- 汇总排名准确（含权重边界用例）；离散度异常标记与倾向性识别在评测场景中验证
- 复核全链路留痕（人/时间/意见/修改记录），归档可检索
